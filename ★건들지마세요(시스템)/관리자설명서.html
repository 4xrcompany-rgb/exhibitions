4XR 기획전 자동화 · 관리자

직원들의 작업을 한곳에 모아 보고
시스템을 개선하는 관리자 설명서

직원들이 각자 컴퓨터에서 작업하면, 작업기록·성공·실패·오류가 내 옵시디언 한 곳으로 모입니다. 나는 그걸 보고 고쳐서, 개선을 직원들에게 자동으로 내려보냅니다. 이 문서는 그 중앙(관리자) 쪽 설정·운영법입니다.

0 전체 그림 — 어떻게 도는가

GitHub 비공개 저장소를 가운데 두고, 내 옵시디언과 직원 컴퓨터들이 연결됩니다.

┌───────── GitHub 비공개 저장소 (중앙) ─────────┐ │ system = 스킬·규칙·스크립트 (내가 고침) │ │ 기록/ = 직원별 작업기록 (직원이 씀) │ │ 개선사항/ · 00_대시보드.md (내가 봄) │ └───────────┬──────────────────────────┬──────────────┘ pull │ (개선 받기) push │ (기록 올리기) ┌───────────┴────────┐ ┌───────┴────────────┐ │ 내 옵시디언 (중앙) │ … │ 직원 컴퓨터 ×N │ │ 대시보드로 확인·개선│ │ 클로드로 작업·채팅 │ └────────────────────┘ └────────────────────┘
🔑

내가 하는 건 딱 두 가지예요. ① 대시보드에서 직원들의 성공·실패·오류를 본다 → ② 반복되는 문제를 규칙(스킬)으로 고쳐 올린다. 그럼 직원들에게 자동 반영됩니다.

1 중앙 저장소 (GitHub) — 이미 됨

모든 자료가 모이는 중앙 창고입니다. 한 번만 만들면 됩니다.

✓
저장소
github.com/4xrcompany-rgb/exhibitions (Private) 로 만들어 이 폴더를 올려둠.
✓
회사 GitHub 아이디 1개 공유
직원 PC는 이 회사 아이디로 GitHub Desktop에 로그인해서 연결합니다. (누가 했는지는 아이디가 아니라 각 기록의 작업자 이름으로 구분되니 문제없음)
✓
비공개 유지
회사 자료이므로 저장소는 반드시 Private. 접근은 회사 아이디로 로그인한 PC만.
🆕

새 저장소를 처음부터 만들 때만 — github.com → New repository → 이름 입력 → Private → Create → 클로드에게 이 폴더를 github.com/…/이름 에 올려줘 라고 하면 연결·업로드해 줍니다.

2 내 옵시디언(중앙) 설정 — 딱 한 번

직원 기록이 여기로 모입니다. 이미 해두었다면 넘어가세요.

1
옵시디언 설치 · 이 폴더 열기
obsidian.md에서 설치 → 첫 화면 “폴더를 보관함으로 열기” → 이 폴더(★4XR_기획전_자동화) 선택 → “제작자를 신뢰…” 클릭.
2
플러그인 2개 설치
설정(⚙) → 커뮤니티 플러그인 켜기 → 둘러보기 → “Git”(개발자 Vinzent) 설치·활성화, “Dataview” 설치·활성화.
3
Git 플러그인 설정 (받기 위주)
설정 → Git → Auto pull interval (minutes) = 10, Pull on startup 켜기. 내가 개선을 올릴 땐 Commit-and-sync 를 씀(아래 §4·§5).
4
대시보드 즐겨찾기
왼쪽 파일 목록 → ★건들지마세요(시스템) → 00_대시보드.md 열고 북마크. 여기서 실패·오류·직원별 집계가 자동 표로 뜹니다.

3 직원에게 배포하기

직원은 사용설명서.html 만 따라 하면 됩니다. 나는 아래 3가지만 챙겨주면 돼요.

1
회사 GitHub 로그인
직원이 GitHub Desktop에 로그인할 회사 아이디를 알려주거나, 내가 각 PC에서 대신 로그인해 줍니다.
2
저장소 주소
github.com/4xrcompany-rgb/exhibitions — GitHub Desktop의 Clone 목록/주소칸에 씁니다.
3
직원 이름
기록에 찍힐 이름(예: 황다빈). 직원이 내 이름 ○○로 WHOAMI 만들어줘 로 등록합니다.
⚠️

“USB로 폴더만 복사”는 금지. 그러면 연결이 안 돼서 기록이 안 올라옵니다. 반드시 GitHub Desktop으로 Clone 해서 받게 하세요. (직원 설명서에도 경고해 뒀습니다.)

4 평소 운영 — 개선 루프

이게 이 시스템의 핵심입니다. 대시보드를 보고, 문제를 규칙으로 고쳐 내려보냅니다.

1
대시보드 확인
00_대시보드.md 를 엽니다. “손봐야 할 것(실패·부분성공)”, “오류 모아보기”, “직원별 건수”가 자동으로 뜹니다. (옵시디언이 10분마다 최신 기록을 받아옴)
2
반복 문제 찾기
여러 직원에게서 같은 오류가 반복되면 그게 우선 개선 대상입니다. (예: “배너 폰트 404”, “이미지 업로드 403”)
3
개선사항으로 정리
★건들지마세요(시스템)/개선사항/ 에 이슈 하나당 파일 하나로 메모해 둡니다.
4
규칙(스킬) 고치기
이 폴더에서 클로드 코드를 켜고 문제를 말하면 규칙을 고쳐줍니다. 예:
배너 폰트가 자꾸 404 나. 스킬에 폰트 처리 규칙 추가해줘
(직접 .claude/skills/…/SKILL.md 를 열어 고쳐도 됩니다.)
5
올리기 → 직원 자동 반영
옵시디언에서 Ctrl+P → “Git: Commit-and-sync” (또는 Push). 직원들은 다음 작업 때 자동으로 받아가 개선된 규칙으로 일합니다.

5 올리기 · 받기 (옵시디언에서)

터미널 없이 옵시디언 명령으로 다 됩니다. Ctrl+P 를 누르고 아래를 칩니다.

↑
내 변경을 올리기
Git: Commit-and-sync — 내가 고친 규칙·개선사항을 커밋하고 GitHub로 올립니다.
↓
직원 기록 받기
Git: Pull — 수동으로 즉시 받기. (평소엔 10분마다 자동으로 받아오니 안 눌러도 됨)

6 막히면

자주 나오는 상황과 해결법.

대시보드 표가 계속 비어 있어요
① 아직 직원 기록이 없을 수 있어요(정상). ② Dataview 플러그인이 설치·활성화됐는지 확인. ③ 옵시디언 Git이 Pull을 하는지 확인.
직원 기록이 안 올라와요
그 직원이 폴더를 GitHub Desktop으로 받지 않고 복사만 했을 가능성. 다시 Clone으로 받게 하세요. 또는 그 PC에서 로그인이 풀렸는지 확인.
올리기(Push)가 안 돼요
GitHub 로그인이 필요합니다. 옵시디언 Git이 자격 증명을 물으면 회사 아이디로 로그인하세요.
직원이 그만뒀어요
그 PC의 GitHub 로그인을 해제하거나, 회사 계정 비밀번호를 바꿔 그 PC의 접근을 끊으세요.
규칙을 고쳤는데 직원에게 반영이 안 돼요
내가 Commit-and-sync(올리기) 를 했는지, 직원 쪽이 Pull(받기) 됐는지 확인. 직원은 다음 작업 시작 때 자동으로 받아갑니다.
한 문장 요약 — 대시보드에서 직원들의 실패·오류를 보고 → 규칙(스킬)을 고쳐 → Commit-and-sync 로 올리면 → 직원들에게 자동 반영. 이 문서는 관리자용이며 ★건들지마세요(시스템) 안에 있습니다. 직원 배포본에는 안 보입니다.
