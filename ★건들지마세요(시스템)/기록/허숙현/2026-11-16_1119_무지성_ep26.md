## ⚠️ 스타일링 스와이퍼 사진이 잘린다 (게시글 22238 · 원인 확인됨)

실제 게시글을 Node 프록시로 열어 재현했다 (`scratchpad/board_check.mjs`).

- 스타일 게시물 사진 = **750 × 1170** (1 : 1.56)
- PC 스타일링 칸 = **484 × 614** (1 : 1.27) · `object-fit: cover` · `object-position: center center`
- → **위아래로 18.7% 잘린다** (사진 1170 중 219px, 위아래 각 109px). 전신컷이라 **발과 머리끝이 날아간다**

원인은 공통 엔진 CSS `fashionrules26.css` 의 한 줄:
```
191: #sub02_section .styling_area { height: 614px; }       /* 폭은 1fr → 484px */
156: #sub02_section .sub02_content { grid-template-columns: minmax(0,45%) minmax(0,1fr); height: 614px; }
```
614px 은 **옆 상품 영역과 높이를 맞추려고** 잡은 값이고, 폭은 남는 자리를 다 가져가 484가 된다.
같은 사진을 쓰는 다른 자리는 비율을 맞춰 놨다 — 법칙 카드 `aspect-ratio: 1/1.57`, 투표 `2/3`.
**PC 스타일링 칸만 1.27 로 유독 납작하다.**

모바일(463행)은 `aspect-ratio: 2/3` = 1.5 라 3.8% 만 잘려 거의 티가 안 난다.

**이번 변경 때문이 아니다.** `styling_index_nos` 로 바꾸기 전에도 같은 칸·같은 규격이었다.

## 이벤트 투표 첫 사진 바꾸기 (2026-11-16)

**지적**: sub01_list 법칙 썸네일과 이벤트 투표 스와이퍼 첫 장이 같은 사진.

return list.map(function(images, order){

## 모바일 법칙 캡션 줄바꿈 지정 (2026-11-17)

| | 앞줄 | 뒷줄 |
|---|---|---|
| 01 | 덩치 큰 남자들의 | 겨울 아우터 고민은 이걸로 끝 |
| 02 | 100kg 이상에게 찰떡인 | 훈남 남사친 아우터 스타일링 |
| 03 | 108kg 근돼 완벽하게 | 꾸며드린 겨울 아우터룩 |

**CSS 가 아니라 settings 쪽에서 처리했다.** 엔진이 `escapeHtml(rule.caption)` 으로 넣기 때문에
caption 에 `<br>` 을 적으면 글자로 나온다. 그래서 개발자 영역에 블록을 하나 더 뒀다.

- `matchMedia("(max-width: 768px)")` 가 참일 때만 `<br>` 을 끼운다 — **PC 는 한 줄 그대로**
- 그래서 **CSS 는 손대지 않았다** (fashionrules26_v3.css 는 이미 올라가 있어 그대로 두면 된다)

## 스타일링 ↔ 이벤트 중복 (2026-11-17)

### 실측

이벤트와 스타일링은 **같은 파일을 쓰진 않았다.** 겹친 건 **착장**이다.

| | 쓰는 곳 |
|---|---|
| sub01 카드 썸네일 | 대표 착장 #1 |
| 스타일링 첫 장 | 대표 착장 #1 ← **썸네일과 완전히 같은 파일** |
| 이벤트 스와이프 | 대표 착장 #2·#3·#4 |

착장 게시물 하나에 사진이 **정확히 4장**(해시로 확인, 서로 다른 사진).
그 4장을 썸네일·스타일링·이벤트가 나눠 쓰고 있어, 같은 옷·같은 사람이 네 번 나왔다.

### 고침

스타일링에서 **대표 착장을 뺐다.** 이벤트가 이미 그 착장을 세 장 보여주기 때문이다.

| | 전 | 후 |
|---|---|---|
| 01 | 22217·22218·22227·22229 | 22218·22227·22229 |
| 02 | 22236·22221·22224·22235 | 22221·22224·22235 |
| 03 | 22234·22231·22230 | 22231·22230 |

겹침 재측정 : **이벤트와 같은 사진 0, 썸네일과 같은 사진 0** (세 법칙 모두).

착장은 기획 엑셀 메모의 촬영 폴더와 1:1 이다 (01=02·03·12·14 / 02=21·06·09·20 / 03=19·16·15).
그래서 **빠진 자리를 다른 착장으로 채우지 않았다.** 기획에 없는 컷을 끌어오는 셈이라서.

### 같이 드러난 문제 — 스와이퍼가 끝까지 안 돈다

| 슬라이드 | 도는 모양 |
|---|---|
| 4장 | 정상 (4장 전부) |
| 3장 | 첫 장이 **한 번만** 보이고 뒤 2장만 반복 |
| 2장 | 둘째 장에서 **멈춘다** |

공통 엔진 `fashionrules26.js` 의 `loopAdditionalSlides: use_loop ? 1 : 0` 탓이다.
콘솔에 Swiper 의 "not enough slides for loop mode" 경고가 찍힌다.

**이건 원래 있던 문제다.** 예전 구성에서도 법칙03(3장)은 22234 가 한 번만 보이고 22231↔22230 만 돌았다.
장수가 줄면서 법칙01·02 까지 드러났고, 법칙03(2장)은 한 장에 멈춘다.

시험 삼아 엔진에서 그 한 줄을 `loopAdditionalSlides: 0` 으로 바꿔 보니 **3장·2장 모두 정상 순환**했다.

| | 지금 엔진 | 한 줄 고친 엔진 |
|---|---|---|
| 01 (3장) | 2장만 반복 | 3장 전부 |
| 02 (3장) | 3장 (첫 장 1회) | 3장 전부 |
| 03 (2장) | **멈춤** | 2장 전부 |

공통 엔진은 지난 회차도 함께 쓰므로 **사용자 승인 전까지 고치지 않았다.**
고치면 파일명을 올려야 한다 (`?v=` 가 아니라 이름).

## 바로잡음 — "대표법칙 스타일링 이미지"는 **법칙 카드 사진**이었다 (2026-11-17)

위 절에서 STYLING 스와이퍼를 건드린 건 **엉뚱한 곳**이었다.
사용자가 가리킨 건 sub01 의 **법칙 카드 큰 사진**이다. 스타일링 변경은 **되돌렸다**(4·4·3 그대로).

### 왜 겹쳐 보였나

착장 게시물 하나에 사진이 **4장뿐**인데 쓰는 자리는 5곳이다.

| 자리 | 전 | 후 |
|---|---|---|
| 법칙 카드 | #1 | **#3** |
| 이벤트 스와이프 | #3·#4·#2 | **#1·#2·#4** |
| 스타일링 첫 장 | #1 (카드와 같은 파일) | #1 |

전에는 **카드와 스타일링 첫 장이 완전히 같은 파일**이었고, 나머지 3장을 이벤트가 썼다.
그래서 같은 옷·같은 사람이 카드·스타일링·이벤트에 네 번 나왔다.

### 지금

- 카드는 **#3 (전신, 지금까지 안 쓰던 포즈)**
- 이벤트는 카드가 안 쓰는 **#1·#2·#4**
- 겹침 : **카드↔이벤트 0, 카드↔스타일링 0**

남는 겹침은 **스타일링 첫 장(#1) ↔ 이벤트 한 장(#1)** 하나다.
사진 4장을 다섯 자리가 나눠 쓰므로 한 쌍은 반드시 겹친다.
눈에 가장 덜 띄는 쪽(멀리 떨어진 두 스와이프 안)으로 밀어 둔 것이다.
완전히 0 으로 하려면 스타일링에서 대표 착장을 빼야 하는데, 그러면 슬라이드가 줄어 스와이퍼가 제대로 안 돈다(위 절 참조).

### 카드는 전신 컷이어야 한다

처음엔 반신·클로즈업 컷(#2 등)을 넣어 봤다. PC 는 괜찮지만 **카드가 세로로 커지는 모바일에서 과하게 당겨 보인다.**
세 법칙 모두 **#3 이 전신**이라 #3 으로 맞췄다. 포즈는 셋 다 다르다.

**검증** : PC 1920 · 모바일 750 양쪽 캡처, 카드 세 장 모두 전신·머리 안 잘림, 겹침 0, 스크립트 오류 0.

## 법칙 카드에 '다른 착장룩' 넣기 (2026-11-17)

위에서 같은 착장의 다른 컷으로 바꿨던 건 **요청이 아니었다.**
사용자가 말한 건 **이벤트에 입은 착장 말고 다른 착장룩**이다. 법칙마다 착장이 3~4개 있으니 거기서 고르면 된다.

| | 카드 착장 | 뭘 입었나 | 이벤트 착장 |
|---|---|---|---|
| 01 | 22218 #4 | 같은 항공점퍼 + 그레이 스웨트 | 22217 |
| 02 | 22221 #4 | 블랙 코듀로이 퍼카라 자켓 | 22236 |
| 03 | 22231 #4 | 아이보리 스타디움 점퍼 | 22234 |

- 사진 순번은 **#4** 로 통일 — **#1 은 스타일링 스와이퍼가 쓴다.**
- 셋 다 **전신 컷**이다. 반신·클로즈업은 카드가 세로로 커지는 모바일에서 과하게 당겨 보인다.

### 공통 파일은 못 하는 일이라 개발자 영역에 넣었다

`renderSub01StyleImages()` 는 카드에 **그 법칙의 index_no 착장**만 넣는다. 순번(`thumb_image_index`)만 고를 수 있고 게시물은 못 바꾼다.
그래서 settings 개발자 영역에 **`CARD_LOOKS` 블록**을 뒀다. 공통 엔진은 건드리지 않았다.

```
var CARD_LOOKS = [
    { post: "22218", image: 4 },
    { post: "22221", image: 4 },
    { post: "22231", image: 4 }
];
```

- 공통 파일이 사진을 **나중에 덮어쓰므로** MutationObserver 로 지켜보다 되돌린다 (`data_card_look` 에 기억).
- 못 불러오면 공통 파일이 넣은 대표 착장 사진 그대로 둔다.
- `thumb_image_index` 와 이벤트 `image_indexes` 는 **승인받은 값(1 / [3,4,2])으로 되돌렸다.**

## 스타일링 사진 랜덤 (2026-11-17)

보여주는 **착장은 그대로**, 각 착장에서 꺼내는 **사진만** 들어올 때마다 바뀌게 했다.
settings 개발자 영역 블록이고 공통 엔진은 안 건드렸다. 끄려면 `STYLING_RANDOM = false`.

**이벤트·카드가 쓰는 사진은 빼고 고른다.**
- 이벤트 : `rules[].event.image_indexes` 를 읽어 그 법칙의 대표 착장에서 제외
- 카드 : `window.FR_CARD_LOOKS` (카드 블록이 내놓는 표)에서 제외

그래서 **각 법칙의 첫 착장(대표 착장)은 늘 같은 사진**이다. 이벤트가 3장을 쓰고 있어 남는 게 한 장뿐이라서.
거기까지 랜덤으로 돌리려면 이벤트 장수를 줄여야 한다.

**검증** (5회 반복)

| 법칙 | 착장별로 나온 사진 가짓수 |
|---|---|
| 01 | 22217 **1종(대표·고정)** / 22218 3종 / 22227 3종 / 22229 3종 |
| 02 | 22236 **1종(대표·고정)** / 22221 3종 / 22224 3종 / 22235 4종 |
| 03 | 22234 **1종(대표·고정)** / 22231 2종 / 22230 2종 |

5회만 돌려서 2종인 것도 있고, 실제로는 3~4종 중에서 고른다.
**이벤트와 겹침 0, 카드와 겹침 0, 못 불러온 사진 0, 스크립트 오류 0.** PC 1920 · 모바일 750 모두.

**알아 둘 것** : 들어올 때마다 화면이 달라지므로, 나중에 "이 사진이 왜 여기 있지" 를 그대로 재현하기 어렵다.
