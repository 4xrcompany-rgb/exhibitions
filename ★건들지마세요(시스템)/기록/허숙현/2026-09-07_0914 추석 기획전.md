### 함정 ① 특이도 ★

**② 세로 크기 조절 지점을 만들었다.**
기존엔 조절할 곳이 아예 없었다 — `id03.png`(1200×800)가 `width:100%` 로 높이를 정해 버려서, 세로를 바꾸려면 이미지를 다시 뽑는 수밖에 없었다.

구조를 한 겹 나눴다.
- `.luckybag_stage` — 영역 높이를 정하는 창. `padding-top:calc(var(--lb-stage-h,800) / 12 * 1%)` (가로 1200 기준이라 세로비 = h/1200 = h/12 %).
- `.lb_frame` — 1200×800 아트워크. 타이포 `top:%` 가 여기 붙으므로 높이를 바꿔도 **서로 안 틀어진다.**

**처음엔 '중앙 기준으로 잘라내는' 방식으로 만들었다가 되돌렸다.** 사용자 지적 — 세로가 줄면 **내용물도 같이 줄어야** 한다. 잘라내면 박스 아랫부분이 없어진다.
→ 프레임 폭을 세로에 비례시킨다. 아트워크 비율이 1200:800 이므로 `프레임폭 / 스테이지폭 = h/800` → `width: min(100%, calc(var(--lb-stage-h,800) / 8 * 1%))`. 남는 좌우는 차콜. `min()` 은 h 가 800 을 넘을 때 가로로 넘치지 않게 묶는 것(이 경우 위아래에 차콜 여백이 붙는다).

`aspect-ratio` 대신 `padding-top %` + `min()` 을 쓴 건 게시판이 도는 구형 모바일 웹뷰까지 확실히 먹이기 위해서다.

**조절 위치 — `stage.height` 한 줄** (설정 블록, `BF_LUCKYBAG.stage` 안)
```js
stage:{
  height:800,   /* ★ 가로 1200 기준 px. 800=원본 / 640이면 위아래 80px씩 잘림 */
```

**검증** — 800/640/520 세 값으로 실측: 스테이지 `1200×800 → 1200×640 → 1200×520`, 프레임 `1200×800 → 960×640 → 780×520` 으로 **비율 1.5 를 유지한 채 통째로 축소**되고 세로를 정확히 채운다. 레이어 좌표는 세 경우 모두 `7,28,86` · `27,16,45` 로 **고정**. 잘리는 곳 없음 = 하한 제약 없음.

### 1. 럭키백 구매 버튼 힌트 툴팁 삭제

### 2. 전 상품 보기 버튼이 회원 혜택 아래에 있던 문제 ★

원인이 **둘** 이었다.

**(a) 모바일 보드에 맞는 타깃이 없었다.** PC 와 모바일의 상품 영역 컨테이너가 다르다.

| | PC (www) | 모바일 (m) |
|---|---|---|
| `.magazine_view_wrap > .padding_02 > .mb10` | **있음** | 없음 |
| `.connect_product_box` | 없음 | **있음** |

기존 타깃 목록엔 `.mb10` / `.goods_list_nth` 뿐이라 **모바일은 무조건 헛탕** → 폴백으로 본문 끝(회원 혜택 아래)에 붙었다. → `.connect_product_box` 를 두 번째 후보로 추가.

**(b) 폴백이 재시도를 죽이고 있었다.** `applyButton()` 이 폴백으로 붙여도 `true` 를 돌려줘서, 재시도 루프(250ms×20)가 **첫 판에 멈췄다**. 상품 영역이 늦게 그려지면 버튼이 회원 혜택 아래에 **영영 박힌다.**
→ `findTargets()` / `placeIn()` 으로 쪼개고, **진짜 상품 영역을 찾았을 때만 `true`**. 폴백은 '임시로 붙여 두고 `false`' 라 계속 찾는다. 나중에 진짜 자리를 찾으면 `#bf_related_tail` 을 제거하고 옮긴다.

## 27차 작업 (후기 유의사항 모달이 안 열리던 문제) ★

26차에 넣은 `review_notice_modal` 이 안 열렸다.

### 원인 — 모달 CSS 가 전부 id 하드코딩
JS 는 `[data-bf-modal]` → `qs('#'+id)` 로 **범용이라 멀쩡했다.** 문제는 CSS 였다.
```css
#coupon_notice_modal.bf_modal,
#gift_notice_modal.bf_modal,
#lotto_notice_modal.bf_modal,
#black_fry_prize_modal.bf_modal,
#black_fry_winner_modal.bf_modal {display:none; position:fixed; …}
```
**새로 만든 id 는 목록에 없으니 아무 규칙도 못 받는다.** `is_active` 는 붙는데 `display:flex` 규칙이 없어 안 열리고, `display:none` 기본값도 없어 본문 끝에 그냥 얹혀 있었다.

껍데기(`.bf_modal`)만이 아니라 **`.bf_modal_content` · `_title` · `_list` · `_list li` · `_list li::before` · `_close` · `_close:hover` 까지 전부 같은 방식**이라, 껍데기만 고쳤을 땐 모달이 열리긴 해도 **내용 박스가 배경·패딩 없이 투명하게** 떴다(1차 수정 후 캡처로 발견).

### 조치 — 컨테이너 기준 범용 선택자로 전환
모달은 전부 `renderModals()` 가 `#black_fry_modal_root` 안에 그린다. 그래서 해당 묶음 **11곳**(PC 7 + 모바일 4)에 `#black_fry_modal_root <같은 꼬리>` 를 한 줄씩 끼워 넣었다. **선택자를 추가만 했고 지운 건 없다**(diff 로 +11줄만 확인).

**특이도가 같아 기존 동작은 그대로다.** 추가한 `#black_fry_modal_root .bf_modal_content` 는 (1 id, 1 class) 로 `#black_fry_prize_modal .bf_modal_content` 와 동일하고, 애초에 **같은 규칙 안에** 들어가므로 캐스케이드 승부가 바뀔 여지가 없다.

**앞으로 모달을 추가하면 CSS 를 손댈 필요가 없다.**

**검증 — 5종 전부 실제로 클릭**

닫힌 상태 6종 모두 `display:none`, 열면 `flex`+`position:fixed`+화면 전체 덮음, 닫기 누르면 다시 `none`. 경품 모달의 투명 배경·패딩 0 은 **자체 오버라이드로 원래 그런 것**(변경 전과 동일). 엔티티 0건, `node --check` 통과.

### 함정 (하네스)
- Playwright `waitForSelector` 기본값이 `state:'visible'` — **닫힌 모달은 영영 안 보이므로** `state:'attached'` 를 써야 한다.

## 30차 작업 (럭키백 애니메이션 대안 3차 — 구형 사이트 조건 반영)

### 먼저 '구형' 의 실체를 측정했다 ★
| 항목 | PC | 모바일 |
|---|---|---|
| 렌더링 모드 | `CSS1Compat` (표준) | `CSS1Compat` (표준) |
| doctype | `<!DOCTYPE html>` | `<!DOCTYPE html>` |
| jQuery | 1.12.4 (2016) | 1.12.4 |
| viewport | (없음) | **`width=750` 고정** |
| 노드 수 | 3,415 | 1,144 |

**렌더링 모드는 구형이 아니다.** 쿼크 모드도 아니고 doctype 도 HTML5. 구형인 건 서버·jQuery·마크업이지 CSS 엔진이 아니다.

게다가 **우리 조각이 이미 쓰고 있는 것**: `var()` · `calc()` · `min()` · grid · flex · `aspect-ratio` · `inset:` · `dvh` · `position:sticky` · `filter:` · 3D transform · `@keyframes` · `will-change` · `:focus-visible` · `object-fit`. `dvh` 만 해도 2022년대 기준선이다.
→ **"옛 브라우저에서 안 돌까" 는 이미 지나간 걱정이고, 진짜 변수는 저사양 폰 성능이다.**

### 진짜 제약 = 모바일 750 고정 뷰포트
`width=750` 이라 실제 폰에서 **약 1.9배 확대**되어 그려진다. 럭키백 스테이지가 750×437(height 700 기준)이고 이게 통째로 확대 합성된다.
→ **매 프레임 리페인트가 생기는 속성은 피해야 한다.** 안전한 건 `transform` / `opacity` 뿐. `box-shadow` · `filter` · `clip-path` · `width/height/top/left` 는 전부 리페인트.

### ★ 앞선 추천 정정
**⑧ 그림자 확산을 `box-shadow` 애니메이션으로 하면 저사양에서 가장 나쁘다.** 같은 그림을 만들려면 그림자를 **별도 레이어**로 두고 transform/opacity 만 움직여야 한다(아래 ⑮).
앞선 것 중 위험한 순: **⑥ clip-path 리빌**(리페인트) > **⑨ 3D 세우기**(확대 뷰포트에서 큰 레이어·구형 GPU 플리커) > 나머지.

### 3차 대안 (전부 transform/opacity 만)
| | 안 | 내용 |
|---|---|---|
| ⑪ | 시차 라이즈 | 세 장이 같은 방향으로 올라오되 **이동 거리를 다르게**(타이포 56/40px, 박스 20px) → 스크롤 연동 없이 깊이감. 가장 저렴 |
| ⑫ | 오버슛 라이즈 | 박스 `translateY(44px → -8px → 0)`. 축 하나뿐이라 최저 비용 |
| ⑬ | 스케일 세틀 | `scale(.92 → 1.02 → 1)`, origin center bottom. **이동이 없어 확대 뷰포트에서 흔들림이 안 보인다** |
| ⑭ | 교차 슬라이드 | 타이포 2장이 서로 반대 방향(-7%/+7%)에서 들어와 교차, 박스는 제자리 opacity+scale |
| ⑮ | 가짜 그림자 레이어 | 박스 뒤 타원 div 를 `scaleX(.6)/opacity .1 → scaleX(1)/opacity .26`. ⑧의 올바른 구현 |
| ⑯ | 라이트 스윕 | 박스 위로 흰 반투명 띠가 한 번 지나감(`translateX` + 부모 `overflow:hidden`) |

**ⓐ 접근성 주의** — WCAG 는 1초에 3회 초과 점멸을 금한다. **깜빡임 2회 / 0.4초** 로 제한할 것(약 5Hz 이나 총 3회 미만). `prefers-reduced-motion` 가드는 이미 있음.

추천: **ⓐ + ⓑ 조합** (타이포는 네온 점등, 박스는 달처럼 떠오름). 컨셉이 한 줄로 설명되고 비용은 지금보다 낮다.
코드 미반영. 프레임 미리보기는 요청 시 제작.

## 32차 작업 (ⓑ 보름달 뜨기 시안 — 프레임 대조)

`lb_moonrise.mjs` — 실제 CDN 소재로 **현재 안 vs ⓑ** 를 나란히 프레임으로 뽑았다. 코드 미반영.

```css
/* 타이포는 '하늘' 처럼 먼저 조용히 뜬다 */
.l1 {animation:m_sky .62s cubic-bezier(.22,.74,.22,1) 0s both;}
.l2 {animation:m_sky .62s cubic-bezier(.22,.74,.22,1) .14s both;}
@keyframes m_sky {from{opacity:0; transform:translateY(14px)} to{opacity:1; transform:none}}

/* 박스는 아래(스테이지 밖)에서 바운스 없이 완만하게 떠오른다.
   stage 의 overflow:hidden 이 지평선 역할을 한다 */
.base {animation:m_rise .92s cubic-bezier(.16,.72,.16,1) .30s both;}
@keyframes m_rise {
  0%   {opacity:0; transform:translateY(46%) scale(.985);}
  16%  {opacity:1;}
  100% {opacity:1; transform:translateY(0) scale(1);}
}
```

**현재 안과의 차이** — 현재는 타이포가 450ms 에 완성되고 600ms 부터 박스가 위에서 떨어져 두 번 튕기며 1250ms 에 끝난다. ⓑ 는 타이포가 150ms 에 거의 다 뜨고 300ms 부터 박스가 아래에서 올라와 800ms 면 안착한다. **체감 속도가 더 빠르고 튐이 없다.** 올라오는 박스가 타이포 아랫부분을 점점 덮어 가는 게 '스카이라인 위로 달이 뜨는' 그림이 된다.

### 함정 (프레임 캡처) ★
`waitForTimeout` 으로 프레임을 뽑으면 **스크린샷 자체가 오래 걸려 실제 경과가 밀린다**(1차 캡처에서 380ms 라벨인데 이미 거의 안착한 상태로 찍혔다).
→ `animation-play-state:paused` + `animation-delay: (기본딜레이 − T)ms` 로 **정확히 T 지점을 고정**해서 찍을 것. 라벨과 그림이 일치한다.

## 33차 작업 (ⓑ 보름달 뜨기 적용)

**설정 세 줄만 바꿨다.** 효과 스위치 구조(25~27차에서 만든 `layers[].effect`)가 그대로 먹었다.
```js
base:{… effect:'moonrise', order:2},
layers:[{… effect:'sky', order:0}, {… effect:'sky', order:1}]
```

**추가한 키프레임 2종** (기존 drop/stamp/fade_up/slide/pop 옆에)
```css
#wrapper_ey .is_in .fxl_sky, #wrapper_ey .bf_is_visible .fxl_sky {animation-name:bf_v_sky; animation-duration:.62s; animation-timing-function:cubic-bezier(.22,.74,.22,1);}
@keyframes bf_v_sky {from {opacity:0; transform:translateY(14px);} to {opacity:1; transform:none;}}

#wrapper_ey .is_in .fxl_moonrise, #wrapper_ey .bf_is_visible .fxl_moonrise {animation-name:bf_v_moonrise; animation-duration:.92s; animation-timing-function:cubic-bezier(.16,.72,.16,1);}
@keyframes bf_v_moonrise {
  0%   {opacity:0; transform:translateY(46%) scale(.985);}
  16%  {opacity:1;}
  100% {opacity:1; transform:translateY(0) scale(1);}
}
```
`translateY(46%)` 로 박스를 스테이지 밖 아래에 두고 시작한다. **`.luckybag_stage` 의 `overflow:hidden` 이 지평선 역할**을 해서, 잘린 아래에서 떠오르는 그림이 나온다.

**등장 간격** `order × .28s` → **`order × .15s`** (0 / .15 / .30). 총 길이 1250ms → **1220ms 지만 체감 안착은 800ms**. 스크롤 트리거 밴드가 좁은 문제(화면 높이의 1%)도 같이 완화된다.

**검증 (실제 등록 상태, 응답 HTML 에 조각을 심어 파싱)**

| 레이어 | 클래스 | animation-name | 길이 | 딜레이 |
|---|---|---|---|---|
| id01 | `fxl_sky` | `bf_v_sky` | 0.62s | 0s |
| id02 | `fxl_sky` | `bf_v_sky` | 0.62s | 0.15s |
| id03 | `fxl_moonrise` | `bf_v_moonrise` | 0.92s | 0.3s |

PC 1440 · 모바일 750 프레임 동일: 0ms 비어 있음 → 150ms 타이포 → 300ms 두 번째 문구 → 450ms 박스가 아래에서 진입 → 800ms 안착.
키프레임 이름 7종 전부 유일, `prefers-reduced-motion` 가드 유효, 엔티티 0건, `node --check` 통과, PC JS 에러 0.

### 함정 (프레임 고정) ★★
27차에서 쓴 `animation-play-state:paused` + 음수 delay 만으로는 **이미 끝난 애니메이션엔 안 먹는다**(경과 시간이 계속 누적되어 항상 종료 상태로 찍힘 — 실제로 8프레임이 전부 같은 그림이었다).
→ **`bf_is_visible` 을 떼고 `animation:none` + 리플로우로 리셋한 뒤**, 정지 상태로 다시 시작시켜야 정확히 T 지점에 선다.

## 36차 작업 (시안 6차 G2·H2·I2 — '이전 구매 후기도 대상' 을 끌어올림, 코드 미반영)

사용자 지적: **이전 구매 후기도 10,000원을 받을 수 있다는 내용이 중요하다.**
5차 시안(G·H·I)에선 이 문장이 스텝 띠 01 아래 **14px 보조 텍스트**로 묻혀 있었다. 사실상 이 이벤트에서 **지금 당장 행동할 수 있는 유일한 경로**(새로 안 사도 됨)인데 위계가 너무 낮았다.

`background:#fff4f0` + 위아래 `rgba(255,59,10,.28)` 라인. 흰 카드와 차콜 띠 사이에서 확실히 떠 보인다.

기획 확인 후 문구를 확정해야 함. **확인 전엔 반영하지 않음.**

### ★ 간격 — margin 이 아니라 '잉크' 로 재야 한다
사용자 지적대로 금액 위아래가 붙어 보였다. 원인은 **초대형 숫자의 라인박스**다.
`line-height` 가 1 미만이면 글자가 라인박스 **밖으로 삐져나오므로**, margin 값과 눈에 보이는 간격이 따로 논다. 시안의 `line-height:.92` + `margin 4px/14px` 는 실제 잉크 간격이 20px 도 안 됐다.

→ `line-height:1` 로 바꾸고 margin 을 크게 잡은 뒤, **렌더 이미지를 픽셀로 분석해 글자와 글자 사이 실제 거리를 측정**했다.

| | 1차(margin 26/30) | 보정 후(margin 26/48) |
|---|---|---|
| 평소 → 금액 | 41px | **41px** |
| 금액 → 후기 1건당 | **23px** | **41px** |

아래쪽만 좁았던 건 **쉼표(,)가 베이스라인 아래로 내려와** 잉크 바닥이 더 낮았기 때문. margin 을 30 → 48 로 올려 좌우 대칭을 맞췄다. 모바일도 34 → 58 (실측 47 / 51px).

### ★ 먼저 잡은 것 — 스타일시트 중괄호 하나가 남아 있었다

|---|---|---|
| 브랜드 | 700 / `#7b8493` | 600 / `#555` |

### ★ 함정 — '공용 규칙'이 실은 공용이 아니었다

| 선택자 | 특이도 | 값 |
|---|---|---|
| `.product_name` | (0,1,0) | 500 |
| **`#wrapper_ey h1…h6`** | **(1,0,1)** | **400 ← 이김** |
| `#ranking_section .ranking_name` | (1,1,0) | 500 ← 이김 |

**즉 이 줄은 처음부터 상품 쪽엔 굵기가 안 먹고 있었다**(PC 의 700 도 마찬가지). → 상품 쪽을 `#wrapper_ey .product_name` 으로 올려 특이도를 맞췄다.

### 합치는 순서를 정한 근거
미디어쿼리는 **특이도를 더하지 않는다.** 따라서 순서가 곧 우선순위이고, 아무렇게나 합치면 같은 특이도 규칙의 승패가 뒤집힌다.

- 합친 블록을 **뒤쪽 블록이 있던 자리**에 뒀다.

원래 : `[블록1] [일반규칙 6,262자] [블록2]`
지금 : `[일반규칙 6,262자] [블록1+블록2]`

→ 그 사이에 있던 **일반 규칙 6,262자가 이제 모바일 블록보다 앞**에 온다. PC 는 미디어 블록이 아예 적용되지 않으므로 영향 없고, **모바일에서만** 순서 관계가 바뀐다.

### 검증 — 계산값 스냅샷 비교 ★
"괜찮겠지" 로 넘기지 않고, 합치기 전/후 **모바일 실렌더 계산값을 통째로 비교**했다.
- 대상 : 래퍼·모달·댓글·스티키·전상품버튼 안 요소 **292개** (같은 종류는 3개까지)

- 모달은 전부 `is_active`, 섹션은 전부 `bf_is_visible`, 비어 있던 상품·랭킹 카드는 만들어서 규칙이 걸리게 함

**결과 : 292개 중 바뀐 속성 1건.** 그마저도 로또 툴팁의 `transform` 인데, `bf_lotto_prize_hint_float ... infinite` 로 계속 떠다니는 애니메이션이라 **캡처 시점 차이**다(-4.563 → -4.708). 실제 변화 아님.

규칙 손실도 확인 — 선택자 블록 692 → 691(합쳐진 `@media` 래퍼 1개만 감소), `review_card` 등 개별 규칙 개수 동일.

### ★ ④ 스티키 클릭이 목표까지 못 가던 원인 — 지연 로딩
실측으로 잡았다. **어느 링크를 눌러도 스크롤이 777 에서 멈췄다.**

| 누른 곳 | 목표 위치 | 실제 도달 |
|---|---|---|
| 쿠폰 | 1950 | **777** |
| 럭키백 | 3152 | **777** |
| 로또(이미 3098 에 있을 때) | 5565 | **3098 (제자리)** |

777 은 **그 시점의 문서 최대 스크롤**이었다. 아래 섹션들이 `initLazyDailySections` · `initLazyRanking` 로 지연 렌더라 클릭 순간엔 문서가 짧고, `window.scrollTo` 는 갈 수 있는 데까지만 가고 끝난다. 뒤늦게 내용이 채워져도 **더 내려가지 않는다.**
→ 한 번 쏘고 마는 대신 **목표에 닿을 때까지 위치를 다시 계산해 재조준**한다.
```js
function scrollToSection(target, offset){
  let tries = 0;
  const aim = () => {
    if(!target || tries >= 10) return;
    const top = target.getBoundingClientRect().top;
    if(Math.abs(top - offset) <= 4) return;      /* 도착 */
    window.scrollTo({top:top + window.pageYOffset - offset, behavior:'smooth'});
    tries += 1; window.setTimeout(aim, 220);
  };
  aim();
}
```
검증 : 회원 혜택·로또 모두 **대상이 화면 상단 72px 에 도착**(이전엔 777 에서 멈춤).


빠뜨렸던 것 두 가지 :
- 모바일 바는 원본을 `cloneNode` 해서 만든다. **복제보다 먼저 붙이면 표시와 `dataset` 표식까지 복제**되어 복제 바엔 감지가 안 걸린다 → 복제 뒤에 붙이고, 표식은 복제되지 않는 **JS 속성**으로 둔다.
- 복제 바는 처음엔 `display:none` 이라 **폭이 0** → 그때 한 번 재고 끝내면 '안 넘침' 으로 굳는다 → `clientWidth` 가 0 이면 판단을 미루고, 화면을 굴릴 때마다 rAF 로 한 번씩 다시 잰다.

검증 : 처음 `남음 228 → 표시 opacity 1`, 끝까지 밀면 `남음 0 → opacity 0`. PC 는 `넘침 0` 이라 저절로 숨는다.

### ④ 모바일 가격 줄바꿈
카드 폭 **169px** 에 판매가·원가·할인율·리뷰가 제멋대로 접혀 2~3줄로 들쭉날쭉했다.
요청 : *"할인전 원가에서 '원' 표시 자동으로 미노출 … 모바일에서 보기만 편하면 됨."*
→ **원가 끝의 `원` 만** `<i class="bf_won">` 로 감싸 모바일에서만 숨긴다. 할인이 없으면 원가 자체가 안 그려지므로 **판매가의 `원` 은 그대로 남는다.**
```js
function wrapWon(value){ return escapeHtml(value).replace(/원\s*$/, '<i class="bf_won">원</i>'); }
```
동시에 줄을 **항상 2줄로 고정** — 판매가가 한 줄을 통째로 쓰고(`flex:0 0 100%`), 원가·할인율·리뷰가 아랫줄에 모인다.
※ 진단 스크립트가 한때 '3줄' 로 보고했는데 이는 **오측정**이었다. `align-items:baseline` 이라 글자 크기가 다른 형제는 같은 줄에 있어도 `top` 이 다르다 — 캡처로 2줄임을 확인했다.

**검증** — 중괄호 700/700, 엔티티 0건, `node --check` 원문·언이스케이프 둘 다 통과, PC JS 에러 0.

## 57차 — PC 스티키가 안 눌리던 진짜 원인 (포인터 캡처)

47차에서 '스크롤이 중간에 멈춘다'로 보고 `scrollToSection` 재조준을 넣었는데, **PC 는 애초에 클릭 자체가 링크에 도달하지 않고 있었다.**

### 추적
게시글 본문 자리(`div.cont.mb60`)에 붙여 **실제 DOM 순서를 재현**한 뒤 이벤트를 찍었다.
```
pointerdown  target = A.sticky_link      efp = A.sticky_link
mousedown    target = A.sticky_link      efp = A.sticky_link
click        target = DIV#sticky_section  ← ★
```
`click` 은 mousedown 대상과 mouseup 대상의 **공통 조상**에서 난다. mouseup 이 컨테이너로 갔다는 뜻.

원인은 가로 드래그 스크롤이다.
```js
el.addEventListener('pointerdown', e => {
  if(e.pointerType === 'touch') return;
  …
  el.setPointerCapture(e.pointerId);   /* ★ 누르자마자 잡는다 */
});
```
포인터를 잡으면 그 뒤 mouseup 이 **잡은 요소**로 돌아간다 → `<a>` 는 click 을 아예 못 받는다. 우리 핸들러도, 브라우저 기본 앵커 이동도 안 걸린다.
`pointerType === 'touch'` 는 위에서 그냥 빠져나가므로 **모바일은 멀쩡했다** — PC 에서만 나던 이유.

### 고침
누르자마자 잡지 말고 **실제로 3px 이상 끌기 시작한 뒤에만** 잡는다. 안 잡았을 땐 요소 밖에서 떼면 `pointerup` 이 안 오므로 창에서도 받아 초기화한다.
```js
el.addEventListener('pointermove', e => {
  …
  if(moved <= 3) return;
  if(!captured){ try{ el.setPointerCapture(e.pointerId); captured = true; }catch(err){} }
  el.scrollLeft = startLeft - dx;
});
window.addEventListener('pointerup', end);
```

### 검증
PC — 럭키백·로또·랭킹·회원 혜택·쿠폰 **전부 대상 top 54 도착**, JS 에러 0.
**날짜 탭도 같이 고쳐졌다** — 같은 `enableDragScroll` 을 쓰기 때문에 PC 에서 날짜 탭 클릭도 먹지 않고 있었다(9.16 클릭 → `is_active` 붙음 확인).
모바일 — 럭키백·로또 탭 모두 스티키 아래끝(160)에 정확히 도착, 회귀 없음.

※ 하네스 교훈 : PC 는 `section.page_cont.padding_01` 이 아니라 **`div.cont.mb60` 안의 `<p><br></p>` 뒤**가 진짜 본문 자리다. 엉뚱한 데 붙이면 게시판 연관상품(`a.link`, z-index 5)이 스티키 위로 올라와 **없는 문제**를 만든다.

**원칙** : 값을 바꾸는 합치기는 하지 않는다. '같은 선택자를 두 번 썼거나, 같은 값을 두 번 썼거나, 같은 걸 가리키는 선택자를 여러 개 나열한' 경우만 손댄다.

### 검증 방법 — 계산값 스냅샷 대조
합치기 전 파일을 따로 보관하고(`index.BEFORE_MERGE.html`), 전/후를 같은 방식으로 렌더해 **요소별 계산 스타일 60여 개 + 박스 크기 + ::before/::after** 를 통째로 찍어 비교했다.
비교가 되게 하려고 **실시간으로 변하는 것들은 고정**했다 — 랭킹·자동화 상품의 진짜 카드는 걷어내고 똑같은 가짜 카드만 남기고, 타이머/업데이트 시각은 고정 문자열로 바꿨다.
(처음엔 이걸 안 해서 "랭킹 원가 폭이 달라졌다"는 가짜 차이가 나왔다.)

노이즈로 확인해 제외한 2가지 — **같은 파일을 두 번 돌려도 달라진다.**
- `.prize_hint_text` : 계속 떠 있는 애니메이션이라 찍는 순간마다 transform 이 다르다
- `margin:0 auto` 요소 : 크롬이 계산값을 `0px 200px` 로 줄 때와 `0px` 로 줄 때가 있다(레이아웃 플러시 타이밍)
