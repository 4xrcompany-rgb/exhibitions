「스프라이트시트로 못 하냐, png 라 무겁다」는 물음에 네 가지를 재 봤다.

**스프라이트시트는 용량이 오히려 는다.** 낱장은 저마다 25색짜리 작은 팔레트를 쓰는데,

### 함정 — 투명 색 번호

처음엔 `max(쓰인 번호)+1` 을 투명으로 썼더니 **캐릭터에 검은 박스**가 생겼다.
그 번호가 **팔레트 크기를 넘으면 브라우저가 tRNS 를 무시한다.**

```python
idx = colors                      # 투명으로 쓸 칸
pal = ... .quantize(colors=colors)
tab = pal.getpalette()
while len(tab) < (idx + 1) * 3:   # 그 칸을 팔레트에 실제로 만들어 넣는다
    tab.append(0)
pal.putpalette(tab)
pal.paste(idx, 투명마스크)
pal.save(..., optimize=True, transparency=idx)
```

지금 hero.png : 모드 P / 투명번호 24 / 팔레트 25색 — 번호가 범위 안이다.

19장 전부 투명 살아 있는 것 확인(알파 0 픽셀 존재), 당첨 연출 렌더도 정상.

스프라이트는 **블프 폴더(2026/11/16)** 에 올라갔는데
`BF_IMG` 는 **추석 폴더(2026/09/14)** 를 가리키고 있었다.

| 폴더 | 들어 있는 것 |
|---|---|
| 2026/11/16 | `event/01/ip/` 19장만 |
| 2026/09/14 | quick · top · pd · luckybag · giftcard 등 나머지 전부 |

`BF_IMG` 를 통째로 11/16 으로 바꾸면 나머지가 전부 깨진다. 그래서 상수를 따로 뒀다.

```js
const BF_IMG    = '.../2026/09/14/HSH/img/';   /* 추석 — 나머지가 아직 여기 */
const BF_IMG_BF = '.../2026/11/16/HSH/img/';   /* 블프 — 새로 올린 것 */
...
base:BF_IMG_BF + 'event/01/ip/',
```

나머지도 11/16 으로 옮기면 `BF_IMG` 를 `BF_IMG_BF` 와 같은 값으로 고치면 끝난다.

### 조사 방법 — 404 캐시를 안 건드리고 확인하기

CDN 은 404 도 캐시하니 함부로 주소를 열면 안 된다.
**쿼리를 붙여(`?p=난수`) 조회하면 캐시 키가 달라져서** 원래 주소는 안 더럽힌다.

```js
im.src = url + '?p=' + Math.random();
```

`fetch` 는 CORS 에 막힌다 — `new Image()` 로 onload/onerror 를 봐야 한다.
이 방법으로 후보 폴더를 훑어 11/16 을 찾아냈고, 19장 전부 뜨는 것까지 확인했다.

## 27회차 (2026-10-28) — 메인 비주얼 위가 잘려 보임

### 잘린 게 아니라 가려진 것

몰 헤더 `HEADER#header` 가 **`position:fixed · z-index:100 · 높이 136~156px`** 인데
기획전이 **`top 0`** 에서 시작해서, 영상 윗부분이 헤더 밑으로 들어가 있었다.
영상 자체는 1920x750 → 1600x625 로 **비율이 정확히 맞고 object-fit:contain** 이라 잘림이 없다.

### 왜 top 0 이 됐나 — 내가 만든 것

게시판 제목 블록을 기획전 CSS 가 숨긴다.

```css
.magazine_view .cont .title, .magazine_view .cont .txt_01, ... {display:none}
```

**그게 위를 받쳐 주고 있었다.** 숨기니 기획전이 페이지 맨 위로 올라붙었다.
(「매거진뷰 고정 블록 불가침」 메모가 가리키던 게 이거다)

### 고친 방법

헤더 높이를 **실행 중에 재서** `#visual_section` 에 그만큼 `padding-top` 을 준다.

```js
function fitTopToHeader(){
  const hd = document.querySelector('#header');
  let pad = 0;
  if(hd && getComputedStyle(hd).position === 'fixed'){
    const r = hd.getBoundingClientRect();
    if(r.top <= 1 && r.height > 0) pad = Math.round(r.height);
  }
  qs('#visual_section').style.paddingTop = pad ? pad + 'px' : '';
}
```

**고정값을 안 쓴 이유** : 위쪽 프로모 띠(46px) 유무에 따라 136 ↔ 156 으로 달라진다.
`load` 와 `resize`(160ms 디바운스)에도 다시 잰다.
헤더가 `fixed` 가 아니거나 화면 위에 없으면 0 — 아무것도 안 한다.

**모바일은 손대지 않았다.** `m.4xr.co.kr` 은 비주얼이 `top 270` 에서 시작해 안 가려진다.

### 확인

실제 게시글에서 같은 로직을 넣어 보니 여백 156px, 가려지는 양 0, 영상 정상 재생.

## 회차 43 — 퀵 뒷배경이 안 보이던 이유 (2026-11-02)

파일은 올라가 있었다(195x166 전부 응답). **내가 그 위에 검정을 88% 덮고 있었다.**

`bgDim` 은 원래 '기획자가 밝은 사진을 넣었을 때 눌러 주는 값' 으로 만든 것이고,
사진이 없을 때 칸이 시안 색으로 보이게 하려고 0.88 로 올려 뒀었다.
그런데 PSD 에서 뽑은 사진은 **이미 시안만큼 어둡다**(최대 밝기 50). 거기에 또 덮으니 새까매졌다.

2배로 캡처해 3배 확대하면 제목만 흐리고 아래 h3 는 또렷하다 (`scratchpad/fp/zoom_text.png`).
→ **고치려면 제목 PNG 를 2배 크기로 다시 내보내야 한다.** 올려 주시면 `srcset` 으로 물려 둔다.
