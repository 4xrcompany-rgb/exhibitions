「스프라이트시트로 못 하냐, png 라 무겁다」는 물음에 네 가지를 재 봤다.

**스프라이트시트는 용량이 오히려 는다.** 낱장은 저마다 25색짜리 작은 팔레트를 쓰는데,

### 함정 — 투명 색 번호

처음엔 `max(쓰인 번호)+1` 을 투명으로 썼더니 **캐릭터에 검은 박스**가 생겼다.
그 번호가 **팔레트 크기를 넘으면 브라우저가 tRNS 를 무시한다.**

```python
idx = colors                      # 투명으로 쓸 칸
pal = ... .quantize(colors=colors)
tab = pal.getpalette()
while len(tab) < (idx + 1) * 3:   # 그 칸을 팔레트에 실제로 만들어 넣는다
    tab.append(0)
pal.putpalette(tab)
pal.paste(idx, 투명마스크)
pal.save(..., optimize=True, transparency=idx)
```

지금 hero.png : 모드 P / 투명번호 24 / 팔레트 25색 — 번호가 범위 안이다.

19장 전부 투명 살아 있는 것 확인(알파 0 픽셀 존재), 당첨 연출 렌더도 정상.

스프라이트는 **블프 폴더(2026/11/16)** 에 올라갔는데
`BF_IMG` 는 **추석 폴더(2026/09/14)** 를 가리키고 있었다.

| 폴더 | 들어 있는 것 |
|---|---|
| 2026/11/16 | `event/01/ip/` 19장만 |
| 2026/09/14 | quick · top · pd · luckybag · giftcard 등 나머지 전부 |

`BF_IMG` 를 통째로 11/16 으로 바꾸면 나머지가 전부 깨진다. 그래서 상수를 따로 뒀다.

```js
const BF_IMG    = '.../2026/09/14/HSH/img/';   /* 추석 — 나머지가 아직 여기 */
const BF_IMG_BF = '.../2026/11/16/HSH/img/';   /* 블프 — 새로 올린 것 */
...
base:BF_IMG_BF + 'event/01/ip/',
```

나머지도 11/16 으로 옮기면 `BF_IMG` 를 `BF_IMG_BF` 와 같은 값으로 고치면 끝난다.

### 조사 방법 — 404 캐시를 안 건드리고 확인하기

CDN 은 404 도 캐시하니 함부로 주소를 열면 안 된다.
**쿼리를 붙여(`?p=난수`) 조회하면 캐시 키가 달라져서** 원래 주소는 안 더럽힌다.

```js
im.src = url + '?p=' + Math.random();
```

`fetch` 는 CORS 에 막힌다 — `new Image()` 로 onload/onerror 를 봐야 한다.
이 방법으로 후보 폴더를 훑어 11/16 을 찾아냈고, 19장 전부 뜨는 것까지 확인했다.

## 27회차 (2026-10-28) — 메인 비주얼 위가 잘려 보임

### 잘린 게 아니라 가려진 것

몰 헤더 `HEADER#header` 가 **`position:fixed · z-index:100 · 높이 136~156px`** 인데
기획전이 **`top 0`** 에서 시작해서, 영상 윗부분이 헤더 밑으로 들어가 있었다.
영상 자체는 1920x750 → 1600x625 로 **비율이 정확히 맞고 object-fit:contain** 이라 잘림이 없다.

### 왜 top 0 이 됐나 — 내가 만든 것

게시판 제목 블록을 기획전 CSS 가 숨긴다.

```css
.magazine_view .cont .title, .magazine_view .cont .txt_01, ... {display:none}
```

**그게 위를 받쳐 주고 있었다.** 숨기니 기획전이 페이지 맨 위로 올라붙었다.
(「매거진뷰 고정 블록 불가침」 메모가 가리키던 게 이거다)

### 고친 방법

헤더 높이를 **실행 중에 재서** `#visual_section` 에 그만큼 `padding-top` 을 준다.

```js
function fitTopToHeader(){
  const hd = document.querySelector('#header');
  let pad = 0;
  if(hd && getComputedStyle(hd).position === 'fixed'){
    const r = hd.getBoundingClientRect();
    if(r.top <= 1 && r.height > 0) pad = Math.round(r.height);
  }
  qs('#visual_section').style.paddingTop = pad ? pad + 'px' : '';
}
```

**고정값을 안 쓴 이유** : 위쪽 프로모 띠(46px) 유무에 따라 136 ↔ 156 으로 달라진다.
`load` 와 `resize`(160ms 디바운스)에도 다시 잰다.
헤더가 `fixed` 가 아니거나 화면 위에 없으면 0 — 아무것도 안 한다.

**모바일은 손대지 않았다.** `m.4xr.co.kr` 은 비주얼이 `top 270` 에서 시작해 안 가려진다.

### 확인

실제 게시글에서 같은 로직을 넣어 보니 여백 156px, 가려지는 양 0, 영상 정상 재생.

## 회차 43 — 퀵 뒷배경이 안 보이던 이유 (2026-11-02)

파일은 올라가 있었다(195x166 전부 응답). **내가 그 위에 검정을 88% 덮고 있었다.**

`bgDim` 은 원래 '기획자가 밝은 사진을 넣었을 때 눌러 주는 값' 으로 만든 것이고,
사진이 없을 때 칸이 시안 색으로 보이게 하려고 0.88 로 올려 뒀었다.
그런데 PSD 에서 뽑은 사진은 **이미 시안만큼 어둡다**(최대 밝기 50). 거기에 또 덮으니 새까매졌다.

## 회차 57 — 스티키 메뉴 ① 칸 사이를 한 곳에서 ② 활성 밑줄을 글자 폭에

### ① 칸 사이 여백 — 왜 불편했나
PC 가 `justify-content:space-between` + `padding:0 max(0px, calc((100% - 1200px)/2))` 였다.
칸 사이가 **적어 둔 값이 아니라 남은 공간을 여덟로 나눈 결과**라,
「조금 벌려 줘」 하면 1200 이라는 숫자를 찾아 고치고 결과를 다시 재야 했다.
(체형별 팬츠 기획전은 `.img_memo_wrap li{width:10%}` 로 탭 개수에 맞춰 바로 조정한다.)

**고친 방식** — `justify-content:center` + `gap` 으로 바꾸고 gap 을 맨 위 한 줄로 뺐다.

```css
#sticky_section,
.bf_mobile_sticky_clone {--bf-tab-gap:60px; --bf-tab-gap-mo:0px; --bf-tab-min-mo:90px;}
```

`--bf-tab-gap` 60px 이 종전 모습과 같다(종전 칸 사이 실측 59~60).
탭이 늘면 이 값만 줄이면 된다. 모바일은 옆으로 넘겨 보는 띠라 칸이 좁아지지 않고
길어지므로 `--bf-tab-gap-mo`(칸 사이)와 `--bf-tab-min-mo`(칸 최소 폭)를 따로 뒀다.

### ② 활성 밑줄 — 왜 어긋났나
`activeItem.offsetWidth - 16` 으로 그렸다(좌우 inset 8). 그런데
- PC : 칸에 좌우 여백이 없어 칸 폭 = 글자 폭 → **밑줄이 글자보다 16px 짧다**
- 모바일 : 칸에 `padding:0 8px` + `min-width:90px` → **글자보다 8px 길고 4px 왼쪽**

**고친 방식** — `stickyUnderlineBox(bar, item)` 를 새로 두고 `Range.selectNodeContents`
로 **글자만** 재서 그 폭 그대로 긋는다. 재지 못하면 종전처럼 칸으로 돌아간다.
밑줄을 그리는 곳이 `initSticky()` 와 `initMobileStickyClone()` 두 함수로 나뉘어 있어
헬퍼는 IIFE 바로 아래(두 함수 바깥)에 뒀다.

### 잰 값
| 폭 | 칸 사이 | 밑줄 어긋남(왼쪽/폭) 전 → 후 |
|---|---|---|
| 1280 | 60 ×8 (종전 59~60) | +8.0 / −16.0 → **0.0 / 0.0** |
| 1920 | 60 ×8 | +7.9 / −15.9 → **0.0 / 0.0** |
| 420 | 0 ×8 | −4.0 / +8.1 → **0.0 / 0.0** |

- 조절 칸 시험 : `--bf-tab-gap` 60/30/96 → 칸 사이 60/30/96 그대로, 밑줄은 계속 0.0/0.0.
  `--bf-tab-gap-mo` 0/10 → 0/10. 값이 바뀌어도 밑줄이 따라온다.
- 탭 9개 × 세 폭 = **27가지 전부 어긋남 0.2px 이내**, 스크립트 오류 없음.
- 칸 자리는 종전 대비 최대 2px 이동(1200 칸 기준 → 가운데 모으기). 눈에 띄지 않는다.

## 회차 58 — 아우터·팬츠 소재 좌우 확장 (메인배너용)

### ★배운 것 — 인물이 든 조각을 주면 모델이 장면을 새로 그린다

### 잰 값
- 이음매 세로줄 밝기차 ÷ 그림 평균 : 아우터 **0.57 / 0.68**, 팬츠 **1.96 / 0.60**.

## 회차 62 — 영상이 되돌아갈 때마다 타이틀도 다시 등장

### 왜 안 나왔나
영상에 **`loop` 가 걸려 있어서 `ended` 이벤트가 오지 않는다.**
타이틀 애니메이션은 페이지가 열릴 때 한 번만 돌고 끝이라, 영상이 두 바퀴째부터는 타이틀이 없었다.

### 고친 방식
`timeupdate` 에서 **재생 위치가 뒤로 간 순간**(`last - now > 0.3`)을 보고 되돌아간 것으로 친다.
그때 `restartVisualTitle()` 로 `.is_titled` 를 뗐다 붙인다.
클래스만 뗐다 붙이면 브라우저가 같은 상태로 보고 안 돌리므로, **사이에 `offsetWidth` 를 한 번 읽어**
다시 그리게 했다.
PC·모바일 영상 둘 다 걸되 `offsetParent === null`(숨어 있는 쪽)은 건너뛴다.

### 첫 등장은 그대로 둠
처음 등장은 여전히 「타이틀 그림이 다 받아졌을 때」다. 영상 재생 시점에 맞추면
**자동재생이 막힌 기기에서 타이틀이 영영 안 나온다.**

### 잰 값 (영상 길이 20.3초, 끝 0.4초 앞으로 보내 되감음)
| | 1.5초 | 4.5초 | 되감긴 뒤 1.2초 | 그 뒤 3.2초 |
|---|---|---|---|---|
| PC 1280 | 1.000 | **0.000** | **1.000** | 0.000 |
| 모바일 420 | 1.000 | **0.000** | **1.000** | 0.000 |

연속 네 바퀴까지 돌려도 **매번 다시 등장**했고, 스크립트 오류 없음.

## 회차 66 — 시계를 「숫자 넘김」으로 (자간 효과는 뺌)

- 숫자 한 자리를 `<span class="ey_d"><i>7</i></span>`, 기호(`:`)를 `<span class="ey_u">` 로 쌓는다.

### 옮겨도 되는지 판정 (`diet3.py`)
앞(p1)의 선언을 뒤(p2)로 내려 보내되, **그 속성을 p1·p2 사이의 어떤 규칙도
같은 요소에 대해 건드리지 않을 때만** 옮긴다.

  (`_match.cjs`, PC·모바일 두 폭을 합침). 추측하지 않는다.
- 비어 있는 결과는 「모른다」로 보고 막는다(`.is_active` 같은 상태 클래스).
- 뒤가 **완전히 덮는** 선언만 죽은 것으로 버린다. 일부만 겹치면 버리지 않는다
  (`margin:0` vs `margin-top:10px`).

### ★세 번 틀렸고 세 번 다 스냅샷이 잡아냈다
1. **문맥으로 걸렀다** — 768 이하에서는 PC 규칙과 모바일 규칙이 **함께** 걸리는데

   `margin-top` 때문에 통째로 사라졌다.
3. **줄임속성을 값으로만 알아봤다** — `expand.json` 에 `flex:0 0 100px` 가 없어
   `{flex}` 로만 보고 `flex:0 0 112px` 와 안 겹친다고 판단, 날짜 탭이 112→100px 로.
   → 값이 없으면 **속성 이름**으로 줄임속성을 알아보게 고쳤다.

1. 비즈호스트에 `/font/` 경로 **CORS 허용**(`Access-Control-Allow-Origin: *`) 요청 ← 제일 깔끔
2. CORS 되는 곳(깃허브+jsDelivr 등)에 올리기
3. base64 로 CSS 에 심기 — 0.9MB 가 1.2MB 로 불어 게시글이 무거워져 **권하지 않는다**
(HeirofLight 를 base64 로 심어 둔 것도 같은 이유였다 — [[cdn-webfont-cors-base64]])

서브셋 파일은 `_폰트_업로드\` 와 CDN 에 그대로 두었다. CORS 만 풀리면 링크 한 줄로 끝난다.

## 91회차 — 전체 코드 다이어트 (더 깎을 게 거의 없다)

종료 임박 띠는 **안 하기로** 했다(코드에 넣은 적 없음, 시안만).

### 한 것
- 그새 늘어난 `@media (max-width:768px)` 2덩이 → **1덩이** (규칙·선언 수 그대로)
- 선택자 649개로 매칭 지도 다시 뜨고(두 폭, 못 맞춘 것 0) `diet3` —
  흩어진 선언 13개를 한 자리로. 규칙 1045 → **1040**
- 427,368 → **427,154 바이트** (−214)

### 왜 조금밖에 안 줄었나 — 재서 확인했다
82회차에서 이미 크게 깎아 **남은 게 거의 없다.**
```
파일 418,291 (CRLF 빼고)
  CSS      210,338 (50%)  ← 그중 base64 폰트 73,192
  JS       198,237 (47%)  ← 그중 공백·들여쓰기 50,094 (25%)
  마크업       9,716 ( 2%)
```
- **base64 폰트 73KB** — CORS 때문에 CDN 에서 못 받아 심어 둔 것([[cdn-webfont-cors-base64]]).
  두 덩이가 **진짜 다른 굵기**(400/700, md5 다름)라 버릴 게 없다.
- **JS 공백 50KB** — 줄이려면 압축(minify)해야 하는데, 허숙현 님이 직접 고치는 파일이라 **안 한다.**
- CSS 공백은 11KB(5%)·주석 2.3KB 뿐. 이미 한 줄에 한 규칙이다.

### 「안 쓰는 이름」 74개는 **대부분 지우면 안 된다**
CSS 에만 있고 마크업·JS 에 안 나오는 이름을 74개 찾았는데 —
`list_box`·`it_box`·`name_box`·`txt_01`·`btn_send`·`btn_up`·`comment`·`lv`·`count_box`·
`btn_reply`·`vote_box`·`btn_align` 등은 **몰이 나중에 붙이는 댓글 영역 마크업**이고,
`fxl_*`·`quick_fx_*` 는 **JS 가 문자열로 조립**하는 이름이다(`'quick_fx_' + item.fx`).
지우면 조용히 깨진다. 1KB 아끼자고 건드릴 일이 아니라 **그대로 뒀다.**
