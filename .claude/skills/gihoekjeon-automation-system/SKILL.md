# 【 기획전 작업 자동화 】

쇼핑몰 **기획전 페이지**와 **배너 세트**를 만드는 자급자족 작업 시스템.
규칙·순서·도구·프롬프트·주의사항·진행상태 관리 방식을 모두 담아, **다른 컴퓨터·다른 사람에게 넘겨도 순서·규칙 변경 없이 그대로 작동**한다.
범용본이라 개별 데이터·진행상태는 포함하지 않는다. 각 사용자는 자기 몰·자기 폴더·자기 소재로 처음부터 시작한다.

---

## 0. 시작 전 환경 점검 ★ 무엇보다 먼저

**막힌 환경에서 시작하면 작업 중반에 반드시 멈춘다.**
작업 폴더를 받자마자, 다른 어떤 일보다 먼저 이것부터 한다.

### 0-1. 접근 테스트 (3초)

```bash
for u in \
  "https://<몰 도메인>/" \
  "https://<몰 CDN 도메인>/" \
  "https://mcp.figma.com/" \
  "<이미지 생성 서비스 결과 CDN>"
do
  echo "$(curl -sS -m 10 -o /dev/null -w '%{http_code}' "$u" 2>&1 | tail -1)  <-  $u"
done
```

`000` 또는 `CONNECT tunnel failed` → **차단**

### 0-2. 차단이면 작업을 시작하지 말고 먼저 알린다

> 지금 클라우드에서 실행 중이라 몰 이미지·피그마 업로드가 막혀 있습니다.
> 이대로 진행하면 중간에 손이 여러 번 필요합니다.
> **「컴퓨터에서 실행」으로 다시 시작**하시면 제가 끝까지 처리합니다.

```
데스크톱 앱 → 새 작업 → 오른쪽 위 "Run this task" → "On your computer"
기본값 변경 → 설정 → Cowork → "Run new tasks in the cloud" 끄기
```

### 0-3. 그래도 클라우드에서 진행한다면

**어느 단계에서 사용자 손이 필요한지 처음에 한 번에 다 말한다.**
중간에 하나씩 튀어나오면 사용자가 지친다.

검증된 우회 경로 하나는 반드시 기억한다 — **피그마 업로드는 외부 샌드박스를 경유하면 뚫린다.**

```
Figma MCP upload_assets → submitUrl 받기
  → 인터넷 열린 샌드박스에서 curl 로 이미지 받고 그 submitUrl 로 POST
  → imageHash 로 피그마에서 채우기
```

이 하나로 배너 작업 전체가 풀린다. 사용자가 이미지를 드래그할 필요가 없어진다.

자세한 내용 → `references/env-check.md`

## 0-A. 하는 일 / 안 하는 일

**한다**
- 참고링크(벤치마크 기획전)를 섹션·구좌 단위로 분해
- 작성용 **구성표 엑셀** + **섹션별 소재 폴더** 생성
- 사용자가 채운 구성표를 읽어 **기획전 HTML** 생성
- 몰에서 **상품 이미지·가격·할인율·링크**, **브랜드 로고·영문명·링크** 자동 수집
- **배너 5규격 7장** 생성 (PC 기준 → 사이즈별 재배치)
- 피그마에 **소재 규격 프레임** 생성 (디자이너가 직접 그릴 경우)

**안 한다**
- 사용자가 채워야 할 카피·쿠폰 문구를 임의로 지어내지 않는다 (요청 시에만 초안 제시)
- 구성표 엑셀을 **처음부터 새로 만들어 덮어쓰지 않는다** (§7 위반 항목)
- 몰 관리자 업로드·게시는 하지 않는다 (파일 전달까지)

## 1. 고정 작업 순서

이 순서는 **변경하지 않는다.**

```
⓪  실행 환경 점검  (§0)  ←  무엇보다 먼저
     └ 막혀 있으면 작업 시작 전에 사용자에게 알린다
①  사용자가 작업 폴더 + "기획전 시작" 을 준다
     └ 참고링크는 엑셀에 넣지 않는다. 이렇게 답한다: "참고 시안 링크를 알려주세요."
       → 사용자가 채팅으로 참고 시안 링크를 준다.
②  참고 시안 링크의 디자인을 클로드가 재현해 보여준다 (승인용)
     └ 재현 대상 = 디자인 시스템: 레이아웃·폭·간격·그리드·타이포·색 + 인터랙션 패턴
       (히어로 페이드 슬라이드, 모션 타이포, 스크롤 리빌, 상품 캐러셀 등).
       실제 값은 참고 페이지 코드에서 추출(computed style/클래스)해 그대로 맞춘다.
     └ ★★실측 원칙 (어기면 사용자가 "이건 왜 달라?"를 반복하게 됨 — 절대 준수) ★★
       (1) 참고 페이지를 인앱 브라우저로 **직접 열어 실측**한다. 기억·추측·예전 재구성본으로
           만들지 않는다. **예전 재구성본(replica 등)은 삭제 대상이고 재사용 금지.**
       (2) **PC 폭(예 1440)과 모바일 폭(예 375) 둘 다** 실측한다. 콜론몰류는 모바일이
           **별도 에셋셋(m-s*)·별도 레이아웃**이다. 모바일을 빠뜨리거나 PC를 축소만 하지 않는다.
       (3) **요소 순서(섹션 안 구성요소의 위→아래 order)까지 원본 그대로** 재현한다.
           예: 원본 모바일 = 헤더 → 대표이미지 → Styling Tip(라벨좌+본문우) → 룩북 → 상품.
           내 편의대로 순서·묶음·정렬을 바꾸지 않는다.
       (4) **원본에 없는 요소를 추가하지 않는다** (예: 탭에 없는 제목/CTA, 히어로에 없는 카피,
           자리표시 그라데이션으로 원본 이미지 대체 등 = 전부 금지). 원본에 있는 것만, 있는 대로.
       (5) 각 구역은 넘기기 전에 **원본 스크린샷과 나란히 대조**(PC·모바일)해 차이를 스스로 잡는다.
           사용자가 지적해서 고치는 게 아니라, 넘기기 전에 일치시켜 둔다.
       (6) ★**모바일 텍스트는 최소 25px 이상**으로 고정한다(nav·카드명·가격·서브카피·섹션서브·카테고리라벨 등 전부).
           25px 미만 폰트 금지(2026-08-10 상향, 기존 15px→25px). 참고 기준: 사용자가 준 `0721/index.html`(상품명 24·서브 28·섹션 31~49px).
           예외는 순수 캡션(쿠폰 유의문구 등)만. 상품 진열 기본값: **PC 5개/줄 그리드 · 모바일 2개/줄**(가로 스와이퍼로 쭉 늘어놓지 않는다).
     └ ★저작권: 참고 사이트의 실제 사진·문구(저작물)는 그대로 복제하지 않는다.
       이미지·텍스트는 자리표시(placeholder)로 두고 사용자가 4XR 것으로 교체한다.
       "전부 똑같이"의 대상은 디자인이지 남의 사진·카피가 아니다.
     └ ★참고 사이트의 고정 header/footer(전역 내비바·전역 푸터)는 재현하지 않는다.
       기획전 본문 섹션만 만든다 (게시판 본문에 들어가면 몰이 header/footer 제공, §5-A).
     └ ★전체 폭(풀블리드): 참고의 히어로/배경 띠가 화면 폭에 꽉 차면 재현본도 꽉 차게 한다.
       페이지를 고정폭(예: 1440px)으로 가두면 넓은 화면에서 좌우에 흰 여백이 생긴다 → 금지.
       배경 띠·히어로는 100% 폭, 본문 콘텐츠(상품 그리드 등)만 max-width로 가운데 정렬.
     └ ★"원본과 똑같이" 요구 시 — 자리표시 대신 참고 페이지의 실제 이미지를 그대로 끌어와 1:1로 보여준다:
       ① 인앱 브라우저 javascript_tool 로 실제 이미지 URL·배경색·px 값을 추출
       ② scripts/download_and_embed.py 로 그 이미지를 내려받아 base64 로 HTML 에 내장
          (Artifact 는 외부 이미지를 못 불러온다 → 내장해야 원본처럼 렌더됨. §7-5 와 같은 이유)
       ③ 스크린샷이 막히면 사용자에게 "브라우저 창을 열어달라"고 요청하거나, 로컬서버(127.0.0.1)로 띄운다.
       이 실제 이미지는 승인용 임시본이다. 게시·배포하지 않고, 승인 후 4XR 촬영컷으로 교체한다.
       저작권 경계(위)는 유지 — 남의 사진을 최종 게시물에 그대로 넣지 않는다.
     └ 재현은 렌더된 시안(Artifact)으로 사용자에게 띄워 보여준다 ("클로드 디자인으로 띄워줘").
③  사용자가 "완벽하게 구현됨" 이라고 승인
④  그때 엑셀 내용을 읽어 콘텐츠(카피·상품코드·브랜드)를 재현 디자인에 채운다
     └ ★상품 진열 방식은 채우기 전에 **반드시 사용자에게 물어본다** (둘 중 택1):
        (A) **엑셀 상품리스트 자동 진열** — 코드만 HTML에 넣고(data-codes), **기획전 HTML 안의
            클라이언트 JS가 런타임에 same-origin `/shop/view.php?index_no=코드`를 fetch→파싱해 카드 렌더.**
            내가 데이터를 긁어 정적으로 박지 않는다. (레퍼런스: 기존 ESCAPE 기획전 로더 JS. 상세 [[gihoekjeon-product-display-method]])
        (B) **비즈호스트 직접 진열** — 상품은 몰(비즈호스트) 관리자에서 직접 진열/관리하고,
            기획전 HTML은 그 진열 모듈/영역을 연결한다(우리가 카드를 하드코딩하지 않음).
        묻지 않고 임의로 한쪽을 진행하지 않는다.
     └ (A) 선택 시: **정적 카드 하드코딩 금지.** JS 자동 로드(fetch by 코드). 파싱: 상품명=og:title, 이미지=`/files/goods/코드/`,
        ★**가격=`meta[property="product:price:amount"]`**(상품별 정확, 백업 `.price`). ★**본문 "숫자원~숫자원" 정규식 금지** — `회원가 A원~B원`은 회원등급 범위이지 할인이 아니다(가짜 할인 사고 2026-08-10). 정상가·할인율은 진짜 취소선(`del,strike,s,.consumer` 등)이 판매가보다 클 때만. 로컬 프리뷰선 상품 안 뜸(몰 배포=same-origin 시 로드).
     └ ★**로더 JS 안에 HTML 엔티티 리터럴 금지** — 게시판에 저장하는 순간 디코드돼 스크립트가 죽고 **상품이 전부 사라진다.** 이스케이프는 DOM 에 맡긴다. 반드시 §7-9 참조.
     └ ★**상품 카드 표기(고정)**: 상품명·가격 **왼쪽 정렬** · 썸네일 **원본 비율 그대로**(img height:auto, 크롭 금지) · 가격순서 **할인가·정상가(취소선)·할인율**.
       ※ ★썸네일 **컨테이너(.thumb)에도 고정 `aspect-ratio` 를 두지 않는다.** 두면 실제 4XR 썸네일이 시안보다 짧을 때 아래에 **빈 줄무늬(빗금) 배경**이 남는다(사고 2026-08-10). 컨테이너는 이미지 높이를 그대로 따라가게 하고, 고정 비율은 **로딩 스켈레톤(.sk)에만** 임시로 쓴다(4XR 기본 600×760).
⑤  구성표 엑셀 · _소재 폴더 · 위치안내 + **필요 이미지 규격 피그마 레이아웃**을 함께 준다
     └ ★⑤에는 **그 기획전에 필요한 이미지 규격을 정리한 피그마 레이아웃이 반드시 포함된다** (선택 아님).
        = 사용자가 만들 이미지(KV/메인, 섹션 소재, 착장, 배너 등)를 **정확한 px 점선 규격 프레임**으로.
        프레임 이름 = 저장 파일명, 프레임 밖 캡션에 규격(px)·저장폴더 표기.
        규격은 재현 단계(②)에서 실측한 원본 값(예: KV 4385×1000, 카드 225×338 등)을 그대로 쓴다.
        프레임↔폴더/파일명 매핑을 작업폴더 `_figma_specs.json` 에 기록(→ "제작 시작" 때 export). Full seat 필요(§7-7).
⑤-b **디자인 확정 게이트** — ⑥ 배너로 넘어가는 트리거는 오직 사용자의 **"기획전 디자인 끝"(디자인 확정 선언)** 뿐이다.
     "배너 만들어줘 / 배너 진행" 같은 말만으로는 절대 ⑥로 가지 않는다.
     └ ★사용자가 수정을 언급했든 안 했든, **⑥ 진입 직전 무조건 피그마·엑셀을 다시 읽어 체크한다.**
        (figma get_screenshot 로 규격 레이아웃 재확인 + 구성표 엑셀 `read_workbook.py` 재파싱)
        바뀐 게 있으면 재현본/구성/규격에 전부 반영한 뒤 진행. "수정했다고 말 안 했으니 그대로" 라고 가정하지 않는다.
     └ 반영·체크 후 → "이대로 **기획전 디자인 끝(확정)** 하시겠어요? 확정하시면 배너 제작 들어갑니다" 라고 확인받는다.
     └ 사용자가 **"기획전 디자인 끝"** 이라고 확정해야 → 그때 비로소 ⑥.
⑥  (**"기획전 디자인 끝" 확정 후에만**) 배너 7장 생성
```

②의 승인(“완벽하게 구현됨”) 전에는 ④(엑셀 콘텐츠 채우기)로 넘어가지 않는다.
디자인이 참고와 다르면, 참고 페이지 코드에서 그 부분 값을 다시 추출해 맞춘다.

**③은 폴더·구성표 엑셀·피그마 소재 규격 프레임을 한 번에 만드는 단계다.**
피그마 규격 프레임 = 사용자가 만들 이미지(섹션 소재 + 배너)를 정확한 px 점선 프레임으로,
프레임 이름 = 저장 파일명, 프레임 밖 캡션에 규격·저장폴더 표기. Full seat 필요(§7-7).
프레임↔폴더/파일명 매핑을 작업폴더의 `_figma_specs.json` 에 기록한다 → "제작 시작" 때 이 매핑으로 export.

★**이미지 워크플로우 트리거(고정)** — 두 단계, 각각 아래 문구가 트리거다:

**(A) 사용자: "엑셀 수정하고 폴더에 이미지 넣었어" (또는 유사)**
   → 클로드: ① 구성표 엑셀을 다시 읽어(`read_workbook.py`) 콘텐츠 변경을 기획전 페이지에 반영한다.
             ② 사용자가 폴더에 넣은 이미지 원본을 **피그마 규격 레이아웃의 해당 프레임(파일명 매칭)에 채워 넣는다**(figma import).
   → 그래야 사용자가 피그마에서 배치·크롭을 보고 다듬을 수 있다.

**(B) 사용자: "피그마 이미지 내보내기" (피그마에서 수정 완료 후)**
   → 클로드: **각 프레임을 프레임 이름(=파일명) 그대로 export**(node.exportAsync / get_screenshot) →
             `_figma_specs.json` 의 지정 `_소재/…` 폴더에 저장 → 기획전 페이지에 반영한다.
   → ★**export는 콘텐츠(이미지)만 깨끗하게**: 규격 프레임의 **점선 stroke·회색 가이드 fill은 절대 JPG에 포함하지 않는다**(그건 디자인이 아니라 가이드). 프레임 stroke/fill을 빼고 export하거나, 이미지들만 합성(PIL 등)해서 뽑는다.
   → ★**사진은 절대 늘리지(stretch)·왜곡하지 않는다.** 원본 비율 유지(높이 맞춰 리사이즈). 프레임을 억지로 채우려 사진을 늘리지 말 것 — 자연 비율로 이어붙이면 폭은 콘텐츠대로(프레임을 콘텐츠에 맞춰 리사이즈). 남는 여백을 회색으로 두지도, 사진 늘려 메우지도 않는다.

파일명은 프레임명이 곧 파일명이라 사용자가 일일이 정하지 않아도 된다. 두 트리거 모두 묻지 말고 그 문구에 반응해 실행.

★**규격 프레임 = 잠금 + 마스크(클리핑) 고정 규칙**: 규격 레이아웃의 각 프레임은 반드시
- **`clipsContent=true`(마스크)** — 이미지를 프레임 안 **자식**으로 넣어, 이미지가 프레임 밖으로 커져도 **프레임 안만 보이게**. 사용자가 이미지 크기·크롭을 자유롭게 조정 가능.
- **`locked=true`(프레임 잠금)** — 사용자가 이미지 만질 때 **레이아웃 프레임이 같이 선택/이동되지 않게**. 프레임은 잠그되, **안의 이미지(자식)는 `locked=false`로 편집 가능**하게 둔다.
- RECTANGLE로 만들지 말고 **FRAME**으로(사각형은 자식·클리핑 불가). 점선 stroke·규격 캡션은 유지.
- import(트리거 A) 시 이미지를 이 프레임의 자식으로 append(위치는 프레임 기준 상대좌표로 보정).

**전부 `_소재/` 안**으로 넣는다. `_소재` 를 만들 때 원본 엑셀부터 그 안에 넣는다.

```
<작업폴더>/                          ← 최상단엔 이 3개만

   ├─ _작업파일/                  ← ★스크립트·json·재현본·_figma_specs 등 중간파일 전부
```

### ③ 섹션구성 열 구조 (고정)

```
A:No  B:사용  C:섹션ID  D:섹션명  E:구좌ID  F:구좌명  G:항목
H:유형  I:내용  J:이미지파일명  K:이미지폴더  L:권장규격  M:가이드
```

- **사용(B)** = `Y`/`N`. N이면 그 구좌를 **아예 그리지 않는다**
- **유형(H)** = `텍스트 / 이미지 / 링크 / 색상 / 숫자 / 선택 / 상품코드 / 자동`
- **내용(I)** = 사용자 입력칸 (파란 글씨)
- **자동** 유형은 몰에서 가져오므로 사용자가 채우지 않는다

|---|---|

| 빨간 글씨 | 수집 실패 · 확인 필요 |

### 네비게이션 항목 켜고 끄기

앵커 네비게이션은 **섹션 존재 여부와 별개로** 메뉴에서만 뺄 수 있어야 한다.
③ 섹션구성의 네비 섹션(예: `S02`)에 구좌 `B02 · 네비 항목` 행을 **섹션 수만큼** 만든다.

```
S02  B02  네비 항목  <섹션명> (S03)   선택   Y
S02  B02  네비 항목  <섹션명> (S04)   선택   N   ← 메뉴에서만 빠짐
```

- 항목명 끝의 `(S0x)` 로 섹션과 매칭한다 → 빌더가 정규식 `\((S\d\d)\)` 로 파싱

### 이미지 내장

확인용 HTML은 **처음 보이는 이미지를 base64로 내장**한다 (오프라인·샌드박스에서도 렌더).
- 상품 썸네일: 440×560 로 리사이즈, JPEG q82
- 브랜드 로고: 260×120 로 리사이즈
- 「더보기」로 펼쳐지는 나머지는 몰 CDN URL 그대로

### 5-A. 몰 게시판 적용 ★ 처음부터 이 형태로 만든다

기획전 HTML 은 게시판 본문 안에 들어간다. 위에 **사이트 메뉴바가 있고 그 아래**에 놓인다.
그래서 `<head>` 맨 위에 **고정 블록**을 넣는다. 기획전이 바뀌어도 이 블록은 그대로다.

```html
<link rel="stylesheet" href="<몰 폰트 CSS>">
<style>
/* ═══ 고정 · 기획전이 바뀌어도 그대로 ═══ */
  콘텐츠 틀 초기화 / 관련상품 상단_TAB / 카테고리 / * box-sizing
  @media 1940 이상 / @media 768 이하
/* ═══ 여기까지 고정 ═══ */
</style>
```

**★ 고정 블록만 얹는다. 디자인은 손대지 않는다.**
섹션 구성·색·타이포·문구를 임의로 바꾸거나, 요소를 지우거나, 새로 짜지 않는다.
「깔끔하게 해달라」는 말은 **디자인을 갈아엎으라는 뜻이 아니다.**

**놓치기 쉬운 3가지**

| | |
|---|---|
| 모바일 카테고리 제목은 `.tit_40` 이 아니라 **`.txt_46`** | 두 선택자를 따로 쓴다 |
| 모바일은 로드 직후 섹션이 1개뿐, 나머지는 AJAX | **MutationObserver 로 다시 잡는다** |
| `.img_memo_wrap li{width:25%}` | **탭 개수에 맞춰** 바꾼다 |

### 스크롤 등장 — 이미지·텍스트가 촤르르

기획전에는 **스크롤에 맞춰 요소가 순서대로 올라오는 연출**을 기본으로 넣는다.

```
KV        로드 직후 타이포 → 오브젝트 → 뱃지 → 하단 카피 순으로 상승
섹션 제목  화면에 들어오면 상승 + 페이드
상품 카드  같은 행 안에서 왼쪽부터 55ms 간격으로 순차 (촤르르)
브랜드 로고 45ms 간격
카테고리 제목 이미지  흑백 → 컬러 (.is-saturated)
```

- `.rv` → `.rv.is-in` 전환 + `IntersectionObserver`, 발동한 요소는 `unobserve`
- 지연은 **행 단위로 리셋**한다 (`(i % 열수) * 간격`). 안 그러면 끝쪽 카드가 몇 초씩 늦는다
- 「더보기」로 늦게 들어오는 카드도 `MutationObserver` 로 다시 잡는다
- 끝난 요소는 `will-change` 를 해제한다
- `transform` 으로 위치를 잡아둔 요소(`translate(-50%,-50%)` 등)에
  **등장용 `transform` 을 덮어쓰면 레이아웃이 깨진다.** 그 요소는 별도 키프레임을 쓴다

고정 블록 전문·체크리스트 → `references/site-block.md`

### 5-A-2. 「기획전 디자인 끝」 → 비즈호스트 납품본 변환 (필수) ★★★

미리보기용 독립 HTML(로컬 렌더용)과, **게시판에 붙이는 납품본은 형태가 다르다.**
사용자가 **「기획전 디자인 끝」** 하면, 게시판 붙여넣기용으로 아래를 **반드시** 만든다.

**① 조각(fragment)으로 만든다** — `<!doctype>·<html>·<head>·<body>` 를 **넣지 않는다.**
게시판이 이미 페이지 틀을 갖고 있다. `<link>(폰트)` + `<style>` + 내용 `<div>` + `<script>` 만 남긴다.
**기존 기획전 html을 그 자리에서 변환한다(overwrite). 별도 납품본·백업 복사본을 만들지 않는다.**
전역 리셋(`*{margin:0;padding:0}`)·`body{}`·`img{}` 는 게시판을 망가뜨리니 **`#래퍼id` 로 스코프**한다(단, `*{}` 를 id로 스코프하면 특이도 때문에 클래스 여백이 깨지므로 box-sizing만 스코프하고 여백 리셋은 heading 등 필요한 것만). 개발용 주석/note 배너는 지운다.

**② 게시판 기본요소를 숨긴다 (= "쓸데없는 문구" 제거)** — 이게 빠지면 게시판 제목·날짜·문구·관련링크·해시태그가 그대로 노출된다(사고 사례: read.php?index_no=21821). `<style>` 맨 위에 §site-block 의 숨김 블록을 넣는다:
```css
#contents .page_info,
.magazine_view .cont .title,
.magazine_view .cont .txt_01, .magazine_view .cont .txt_02, .magazine_view .cont .txt_03,
.magazine_view .cont .txt_info,
.magazine_view .line_01,
.magazine_view .relate_link, .magazine_view .hashtag_box{ display:none; }
.magazine_view{ width:auto; } .magazine_view .cont{ margin-bottom:0 !important; }
@media(max-width:768px){ .page_cont.padding_01{ padding:0; margin-bottom:0 !important; }
  .page_view_top > *{ display:none; } #wrap{ overflow:initial; } }
```
**PC·모바일 둘 다** 적용한다(모바일은 `.page_view_top`·`.page_cont` 계열이 따로다).
정답 형태 예시 = 사용자가 준 `0721_여름_반팔/index.html`, 올바른 게시글 = read.php?index_no=21789.

**③ 몰 내부 자원 사용** — 게시판이 이미 로드한 jQuery·Swiper 를 쓸 수 있다(우리 JS가 바닐라면 그대로 자급자족해도 됨). 폰트는 `<link>` 로 얹는다. 상품은 코드만 넣고 JS가 런타임 fetch(§1-④, [[gihoekjeon-product-display-method]]).

**③-b 스크롤 탭(상단 카테고리 네비) = `position:sticky` (레퍼런스 0721과 동일) ★** — 사용자 확정(2026-08-10):
- **PC: `top:0`** — 스크롤 내리면 탭이 맨 위에 노출, 올리면 4XR 사이트 헤더(z:100)가 그 위를 덮어 가려짐(4XR 헤더는 스크롤 방향에 따라 hide/show 됨).
- **모바일: `@media(max-width:768px){ .snav{top:100px} }`** — 모바일 4XR 메뉴(≈100px) **바로 아래에 딱 붙게**.
- 탭 **z-index 는 헤더(100)보다 낮게(90)** — 그래야 올릴 때 헤더가 덮는다.
- 탭은 **히어로/인트로 다음(상품 영역 앞)** 에 흐름상 배치. show/hide 슬라이드 연출은 뺀다.
- ★★ **래퍼/조상에 `overflow-x:hidden`(또는 overflow:hidden) 절대 금지** — 스크롤 컨테이너가 되어 sticky 가 깨진다(이걸로 "안 붙음" 사고). 가로 넘침은 마퀴 등 개별 요소에서 `overflow:hidden` 으로 막고 래퍼엔 두지 않는다. (fixed+센티넬 방식은 여백이 생겨 폐기 — sticky 로 한다.)
★ **래퍼/조상에 `overflow-x:hidden`(또는 overflow:hidden) 을 두면 sticky 가 깨진다** — 스크롤 컨테이너가 되어 탭이 안 붙는다. 가로 넘침은 마퀴 등 **개별 요소에서 `overflow:hidden`** 으로 막고, 래퍼엔 두지 않는다.

**④ IDE 없는 작업자용 「복사」 파일을 만든다** — 작업자 PC엔 VS코드가 없다. 크롬으로 HTML을 열면 코드가 아니라 화면이 뜬다. 그래서 **`<기획전명>_비즈호스트_붙여넣기.html`** 를 만든다: 「코드 복사」 버튼 + 미리보기 textarea + 3단계 안내. 작업자는 크롬으로 열고 버튼 눌러 복사 → 비즈호스트 게시판 **소스(HTML) 모드**에 붙여넣기.
- ★ 코드에 `</script>`·`&quot;` 가 들어있어 **textarea/​script에 raw로 넣으면 깨진다. 반드시 base64로 임베드**하고 클릭 시 `atob`→`decodeURIComponent(escape())` 로 디코드해 복사한다(생성 스크립트로 만든다). clipboard API 실패 시 `execCommand('copy')` 폴백.
- 이 파일은 「복사 도구」이지 기획전의 백업본이 아니다(①의 백업 금지와 무관).

## 7. 주의사항 — 실제로 사고가 났던 항목

이 절은 **전부 실제 사고 기록**이다. 무시하면 같은 사고가 반복된다.

### 7-1. 엑셀 덮어쓰기 사고 ★★★

**증상**: 내가 쓴 내용이 사라지거나, 사용자가 채운 내용이 사라진다.

**원인**: 사용자가 엑셀을 열어둔 채로 내가 파일을 쓰면, 이후 사용자가 저장할 때 **화면에 떠있던 옛 내용이 내 파일을 덮어쓴다.**

**규칙**
1. 구성표 엑셀을 **처음부터 새로 만들어 덮어쓰지 않는다.** 사용자 파일을 읽어 **바뀌는 칸만** 고친다
2. 쓰기 전 **`~$<파일명>.xlsx` 임시 파일 존재 여부로 열림 상태를 확인**한다. 열려 있으면 쓰지 않고 알린다
3. 구조 변경(행 추가 등)이 필요하면 **먼저 사용자에게 알리고** 진행한다
4. 채팅에 올린 파일은 사본이다. **사용자는 폴더 파일만 연다**고 명확히 안내한다

```bash
# 열림 여부 확인
ls -a <작업폴더> | grep '^~\$' || echo "닫혀 있음"
```

### 7-2. 스테일 캐시 사고 ★★★

**증상**: 사용자는 수정했다는데 내가 읽으면 옛날 내용이다. **사용자를 의심하게 된다.**

**원인**: 파일 스테이징 계층이 캐시된 사본을 넘겨준다.

**규칙**: 구성표를 읽을 때는 **반드시 사용자 기기에서 직접 파싱**한다. 스테이징 사본을 믿지 않는다.

```
device_bash 로 xlsx(zip)를 직접 열어 sharedStrings + sheetN.xml 을 파싱
→ 결과를 JSON 으로 기기에 쓰고, 그 JSON(새 파일이라 캐시 없음)만 가져온다
```

구현 → `scripts/read_workbook.py`

읽은 뒤에는 **직전 스냅샷과 diff** 해서 “사용자가 바꾼 것”을 먼저 보고한다.

### 7-3. CSS 퍼센트 패딩 함정

만든 뒤에는 반드시 요소 박스를 측정해 검증한다.

```js
document.querySelectorAll('.tri,.sticker').forEach(e => e.getBoundingClientRect())
```

### 7-4. URL 대괄호 미인코딩

몰 CDN 파일명에 `[1]` 같은 대괄호가 섞이는 경우가 있다.

```python
from urllib.parse import quote
url = CDN + quote(path, safe='/._-')     # [ ] → %5B %5D
```

### 7-9. 게시판 저장 시 본문 JS 가 깨진다 ★★★ — 엔티티 리터럴 금지

**증상**: 어제까지 잘 나오던 **상품 진열이 통째로 사라진다.** 상품코드도 몰도 멀쩡한데 아무것도 안 뜬다.
콘솔에 `SyntaxError: Unexpected string`, 상품 fetch 요청 **0건**, `.pgrid` 가 전부 자식 0개·높이 0.

**원인**: 몰 게시판 편집기가 저장할 때 본문의 **HTML 엔티티를 디코드**한다.
`&amp;`→`&` · `&lt;`→`<` · `&gt;`→`>` · `&quot;`→`"` · `&#39;`→`'`.
그래서 `<script>` 안에 엔티티 **글자**를 써 두면 문자열 리터럴이 깨지고 스크립트가 통째로 죽는다.

실제 사고(2026-08-10, 기획전 21821): 로더 `esc()` 의 이스케이프 맵에 있던 `&quot;` 가 저장 후 `"` 로 풀리면서
`'"':"""` 처럼 따옴표 3개가 붙었고 **8행 109열에서 스크립트 전체가 죽었다.** 그 한 줄만 고치니 상품 30개가 즉시 정상 렌더됐다.
→ **"상품데이터 연결"이 범인이 아니라 "관리자에서 저장한 것"이 범인이다.** 원인을 상품·몰 쪽에서 찾으면 못 찾는다.

**규칙**
1. **`<script>` 안**에 HTML 엔티티 글자(`&amp;` `&lt;` `&gt;` `&quot;` `&#39;`)를 절대 쓰지 않는다.
   **`esc()` 한 곳만 보고 끝내지 않는다.** 같은 사고에서 `abs(clean(s).replace(/&amp;/g,"&"))` 도 깨져 있었다 —
   이건 저장 후 `replace(/&/g,"&")` 가 되어 **문법 에러 없이 조용히 무력화**된다(이미지 URL 언이스케이프 실패).
2. ★★**HTML 속성 안의 JSON 이 더 위험하다.** `data-cats="[{&quot;cat&quot;:…}]"` 처럼 JSON 을 엔티티로 넣으면,
   저장 시 `&quot;`→`"` 로 풀리면서 **속성이 첫 따옴표에서 잘려 값이 `[{` 만 남는다.** `JSON.parse` 가 죽고
   `catch(e){}` 에 먹혀 **에러 하나 없이 그 섹션만 통째로 사라진다.**
   (실사고: 착장 모아보기. 상품 그리드는 `data-codes="691317,691318"` 처럼 숫자·쉼표뿐이라 멀쩡했다.)
   → **데이터를 속성에 넣지 말고 `<script>` 안 JS 변수로 옮긴다.**
   ```js
   var LOOK_CATS=[{"cat":"비치 에센셜","codes":["691317","691318"]}];   // script 안이라 엔티티 불필요
   ```
   ```js
   var cats=(typeof LOOK_CATS!=="undefined"&&LOOK_CATS)?LOOK_CATS:[];   // getAttribute 대신
   ```
   속성에 남겨야 한다면 **따옴표·엔티티가 안 들어가는 형태만** 쓴다(숫자·쉼표·base64 등).
3. 엔티티 문자열 자체가 필요하면 **유니코드 이스케이프 `\u0026`** 로 쓴다. 편집기가 `\u0026amp;` 는 못 알아본다.
   ```js
   return {"&":"\u0026amp;","<":"\u0026lt;",">":"\u0026gt;",'"':"\u0026quot;","'":"\u0026#39;"}[c];
   .replace(/\u0026amp;/g,"\u0026")
   ```
   ※ `createElement("div").textContent → innerHTML` 로 대체하지 말 것 — **따옴표를 이스케이프하지 않아**(`&` `<` `>` 만)
   결과를 속성값(`alt="…"`)에 넣으면 마크업이 깨진다.
4. **저장할 때마다 재발한다.** 본문을 다시 저장했으면 **매번** 5·6번을 다시 돌린다.
5. 올리기 **전** — 로컬에서 "저장 후"를 시뮬레이션해 검증한다. **엔티티 0건이 목표다.**
   ```bash
   python3 - <<'EOF'
   import io,re,html
   c=io.open("본문.html",encoding="utf-8").read()
   print("엔티티 잔존:", len(re.findall(r'&(?:amp|lt|gt|quot|#\d+);', c)), "건  ← 0 이어야 한다")
   sc=re.findall(r'<script[^>]*>(.*?)</script>', c, re.S)[0]
   io.open("now.js","w").write(sc); io.open("after.js","w").write(html.unescape(sc))
   EOF
   node --check now.js && node --check after.js    # 둘 다 통과해야 한다
   ```
6. 반영 **후** — 인앱 브라우저에서. ★로더가 **IntersectionObserver 지연로딩**이면 **스크롤해야 채워진다.**
   스크롤 없이 "안 뜬다"고 판단하지 말 것.
   ```js
   document.getElementById('sec-look').scrollIntoView({block:'center'});
   await new Promise(r=>setTimeout(r,5000));
   ({빈그리드:[...document.querySelectorAll('.pgrid')].filter(g=>!g.children.length).length,
     착장:document.getElementById('look-random').children.length})
   ```
   → `빈그리드:0` · `착장:0 초과` 여야 정상. 하나라도 어긋나면 **완료 보고하지 않는다.**
7. 사용자가 "○○가 사라졌다"고 하면 **몰·상품코드를 의심하기 전에 이 항목부터** 확인한다.
   섹션 하나만 사라졌으면 **그 섹션이 쓰는 속성 데이터**를, 전체가 죽었으면 **script 문법**을 본다.


### 7-10. 한글 배치파일(.bat)은 UTF-8 로 저장하면 깨진다 ★★ — CP949 로 저장

**증상**: 배포용 `.bat`(4XR_시작.bat, ➊➋➌➍ 등)을 더블클릭하면 한글이 깨지고
`'.Git'은(는) … 배치 파일이 아닙니다` 같은 **"그런 명령 없다" 에러가 쏟아진다**(사고 2026-08-10).

**원인**: 한글 Windows 의 cmd 는 배치파일을 **CP949(EUC-KR)** 로 읽는다. 파일이 **UTF-8**(Write/Edit 도구 기본값)이면
한글 주석·echo·경로가 잘못 디코드돼 그 깨진 바이트가 명령으로 해석된다. `chcp 65001` 을 넣어도 소용없다(파싱은 그 전에 일어남).

**규칙**
1. **한글이 든 `.bat` 은 반드시 CP949 로 저장한다. UTF-8 금지.** Write/Edit 는 UTF-8 로 저장하므로 만든 뒤 **PowerShell 로 CP949 재인코딩**:
   ```powershell
   $t=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)
   [IO.File]::WriteAllText($p, ($t -replace "`n","`r`n"), [Text.Encoding]::GetEncoding(949))
   ```
   ※ 이후 수정도 **PowerShell 로**. Edit/Write 로 CP949 .bat 을 건드리면 UTF-8 로 되돌아가 또 깨진다.
2. **`chcp 949`** 를 쓴다(`chcp 65001` 금지). 줄바꿈은 **CRLF**.
3. **CP949 에 없는 문자 금지** — 동그라미 숫자(➊➋➌➍)·═·▶ 등은 `?` 로 깨진다. `=`·`-`·`>`·`*` 로 대체. (파일명의 ➊ 등은 NTFS 라 괜찮지만 .bat **내용**엔 쓰지 않는다.)
4. `.gitattributes` 에 **`*.bat -text`** — clone 시 인코딩/줄바꿈이 안 깨지게 바이너리로 고정.
5. **.bat 안에서 한글 이름(WHOAMI 등)을 `echo >` 로 쓰지 말고** PowerShell 로 UTF-8 저장(환경변수는 Unicode 라 안전):
   `powershell -Command "[IO.File]::WriteAllText('%DEST%\WHOAMI.txt',$env:WORKER,(New-Object System.Text.UTF8Encoding($false)))"`
   ※ `.ps1` 은 한글이 문자열이라 깨져도 안 죽지만, **`.bat` 은 명령으로 해석돼 죽는다** — .bat 이 특히 위험.

## 10. 진행상태 관리

범용본이라 개별 진행상태는 포함하지 않는다. 각 작업 폴더에서 **파일 존재 여부로 단계를 판정**한다.

| 폴더 상태 | 현재 단계 |
|---|---|
| 환경 점검 전 | ⓪ — 먼저 §0 을 실행한다 |
| 원본 엑셀만 있음 | ① — 구성표부터 만든다 |
| `_소재/` + 구성표 있음 | ③ 완료 — 사용자 입력 대기 |
| 구성표에 내용이 채워짐 | ⑤ 가능 — “엑셀 반영해줘” 대기 |
| `기획전.html` 있음 | ⑤ 완료 |
| `_소재/10_배너/*.jpg` 있음 | ⑥ 완료 |

새 폴더를 받으면 **먼저 이 표로 현재 단계를 판정하고 시작한다.**

## 11. 작업기록 남기기 & 중앙 동기화 (매 작업 종료 시 필수)

기획전 작업(⑤ HTML 완성 또는 ⑥ 배너 완성)이 끝나면 **항상 아래를 수행한다.**
중앙(관리자) 옵시디언으로 성공·실패·오류가 자동 수집되어 개선에 쓰인다.

**① 작업자 확인** — 저장소 루트 `WHOAMI.txt` 를 읽어 작업자 이름을 얻는다.
없으면 사용자에게 한 번 묻고 `WHOAMI.txt` 를 만든다.

**② 기록 파일 작성** — `★건들지마세요(시스템)/templates/작업기록.md` 를 복사해
`★건들지마세요(시스템)/기록/<작업자>/<날짜>_<기획전명>.md` 로 저장하고, 프론트매터를 이번 작업 기준으로 채운다.
- `상태` = 성공 / 실패 / 부분성공 (막힌 게 있었으면 부분성공 이상 솔직하게)
- `오류` = 이번에 실제로 났던 문제 · 유형 · 어떻게 넘어갔는지. **없으면 비운다.**
- 본문 3섹션(잘된 점 / 막힌 점·오류 / 개선 요청)을 이번 작업의 실제 내용으로 채운다.
- 지어내지 않는다. 문제가 없었으면 "없음" 이라고 쓴다.

**③ 중앙에 올리기 — 자동이다. 내가 할 일은 없다.**
기록 파일을 만들어 저장하는 것까지가 내 일이다. 업로드는 **윈도우 작업 스케줄러에 등록된
`sync_log.ps1` 이 30분마다 자동 실행**해서 `기록/` 만 커밋·pull --rebase·push 한다.
(등록: `_처음설치_한번만/➌_자동기록동기화.bat` — 컴퓨터마다 최초 1회. 옵시디언 Git 자동동기화도 이중으로 켜진다.)

- ★**사용자에게 "동기화 눌러주세요 / Push 해주세요" 라고 하지 않는다.** 자동이다.
- ★코워크에서는 **내가 직접 `git push` 할 수 없다** (마운트 환경 네트워크 차단, 403). 시도하지 않는다.
  `git add`·`git commit` 은 로컬이라 가능하니, 기록을 커밋까지 해두면 다음 자동 실행 때 함께 올라간다.
- 기록이 안 올라간 것 같으면 확인 순서:
  ① 사용자에게 `%TEMP%\4xr_sync.log` 내용을 물어본다
  ② 로그 자체가 없으면 그 컴퓨터는 아직 등록 전 → `➌_자동기록동기화.bat` 더블클릭 안내
  ③ 로그에 인증 오류가 있으면 → GitHub Desktop 로그인 상태 확인 안내

**주의:** 직원은 **자기 이름 폴더에만** 쓴다. 시스템 파일(`.claude`, `CLAUDE.md`, 스킬)은
관리자만 수정한다. 이 단계에서 `git add` 는 `★건들지마세요(시스템)/기록/` 로 한정한다(스크립트가 그렇게 한다).
