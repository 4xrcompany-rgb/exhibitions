# 주의사항 전체 목록

전부 **실제로 사고가 난 항목**이다. 각 항목에 증상 → 원인 → 규칙 순으로 적었다.

---

## 1. 엑셀 덮어쓰기 ★★★

**증상**
- 내가 추가한 행이 사라진다
- 사용자가 채운 내용이 사라진다
- 같은 수정을 여러 번 하게 된다

**원인**
사용자가 엑셀을 열어둔 채로 내가 파일을 쓰면, 이후 사용자가 저장할 때
**화면에 떠있던 옛 내용이 내 파일을 통째로 덮어쓴다.**
반대로 내가 통째로 새로 만들면 사용자 입력이 날아간다.

**규칙**
1. 구성표 엑셀을 **처음부터 새로 만들어 덮어쓰지 않는다.** 사용자 파일을 읽어 **바뀌는 칸만** 고친다
2. 쓰기 전 열림 상태를 확인한다
   ```bash
   ls -a <작업폴더> | grep '^~\$'   # 결과 있으면 열려 있음 → 쓰지 않는다
   ```
3. 구조 변경(행 추가)이 필요하면 **먼저 사용자에게 알린다**
4. 채팅에 올린 파일은 사본이다. **폴더 파일만 연다**고 명확히 안내한다
5. 행을 삽입할 때 이미지가 박힌 시트는 앵커가 어긋난다.
   → 이미지 없는 시트에 넣거나, 시트를 다시 그린다

---

## 2. 스테일 캐시 ★★★

**증상**
사용자는 “수정하고 저장했다”는데 내가 읽으면 옛날 내용이다.
→ **사용자를 의심하고 “수정이 안 들어와 있다”고 잘못 보고하게 된다.**

**원인**
파일 스테이징 계층이 캐시된 사본을 넘겨준다. mtime 은 최신인데 내용은 옛것일 수 있다.

**규칙**
1. 구성표를 읽을 때는 **사용자 기기에서 직접 파싱**한다
   ```
   device_bash → xlsx(zip)를 직접 열어 sharedStrings.xml + sheetN.xml 파싱
              → 결과를 새 JSON 파일로 기기에 저장
              → 그 JSON 만 가져온다 (새 파일이라 캐시 없음)
   ```
2. 읽은 뒤 **직전 스냅샷과 diff** 해서 “사용자가 바꾼 것”을 먼저 보고한다
3. 사용자가 “내 폴더에서 수정했다”고 하면 **의심하기 전에 이 항목을 먼저 점검**한다
4. 파싱용 임시 JSON은 작업 후 `_to_delete/` 로 치운다

## 3. CSS 퍼센트 패딩

`padding-top: 22%` 는 **부모의 너비** 기준이다.
부모가 1870px이면 411px이 되어 요소가 프레임 전체를 덮는다.

→ 폭이 큰 컨테이너 안에서는 **퍼센트 패딩을 쓰지 않는다.** px 또는 em.
→ 만든 뒤 `getBoundingClientRect()` 로 반드시 검증한다.

---

## 4. URL 대괄호 미인코딩

CDN 파일명에 `[1]` 같은 대괄호가 섞이면 **브라우저에서만 이미지가 깨진다.**
`curl` 은 되기 때문에 원인을 찾기 어렵다.

```python
from urllib.parse import quote
url = CDN + quote(path, safe='/._-')     # [ ] → %5B %5D
```

---

## 5. 샌드박스 외부 이미지 차단

클라우드 컨테이너의 브라우저는 외부 CDN에 못 붙는 경우가 있다 (`ERR_CONNECTION_RESET`).
`curl` 은 프록시를 타서 되지만 브라우저는 안 된다.

→ 검증용 스크린샷을 찍을 때는 **이미지를 미리 curl로 받아 base64 내장**한다.
→ 사용자 PC에서는 정상이므로 이것을 “안 되는 것”으로 보고하지 않는다.

---

## 6. 웹폰트 CDN 스텁

`cdn.jsdelivr.net` 에서 woff2 를 직접 받으면 **100바이트짜리 리다이렉트 스텁**이 받아지는 경우가 있다.

```bash
npm pack pretendard && tar xzf pretendard-*.tgz
ls package/dist/web/static/woff2/
```
받은 파일 크기를 확인한다. 정상이면 700KB 이상.

---

## 7. 파일 삭제 불가

사용자 기기 마운트에서 `rm` / `rmdir` / `unlink` 는 막혀 있다.

→ 같은 폴더 아래 **`_to_delete/` 를 만들어 `mv`** 한다
→ 사용자에게 “그 폴더를 직접 지워주세요”라고 알린다

---

## 8. 피그마 seat 한계

**View seat** 은
- 에이전트로 디자인을 편집할 수 없다 (읽기 전용 대화만)
- MCP 도구 호출 한도가 낮아 몇 번 만에 막힌다

→ 작업 전 `whoami` 로 seat 확인
→ View 면 사용자에게 Full seat 필요를 알리고 **HTML→JPG 파이프라인으로 우회**

---

## 9. 폴더 접근 권한

작업 폴더 밖의 참고 자료는 접근 권한이 없다.
→ 경로를 확인한 뒤 **필요한 최소 폴더만 한 번에** 요청한다. 여러 번 나눠 묻지 않는다.

## 10. 사용자 지시 준수

| 사용자 말 | 해야 할 것 |
|---|---|
| “규칙 삭제해줘” | 즉시 버리고, **무엇을 버렸는지 목록으로** 확인시킨다 |
| “숨기지 말고 없애” | CSS 숨김이 아니라 **마크업 제거** |
| “선택이 불가해” | 그 선택을 가능하게 하는 **구좌를 엑셀에 추가**한다 |
| “나는 ○○를 아예 모른다” | 기초부터 설명한다. 전문 용어를 전제하지 않는다 |
| “예시 넣을게” | 그 예시를 **기준으로 삼는다.** 임의로 스타일을 정하지 않는다 |

## 11. 보고 태도

- 내가 틀렸으면 **먼저 인정하고 원인을 말한다.** 사용자를 의심한 경우 특히 그렇다
- “빠진 것”과 “살리는 법”을 사용자가 되묻기 전에 먼저 말한다
- 진행 중 방향이 바뀌면 한 줄로 알리고 계속한다
